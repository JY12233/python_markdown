# `to_datetime`

`pd.to_datetime()` 是 Pandas 库中用于**时间序列处理的核心函数**。它的主要作用是将各种格式的数据（如字符串、整数、时间戳等）统一转换为 Pandas 标准的 `datetime64` 类型。

一旦数据被转换为 datetime 类型，你就可以轻松地进行时间差计算、按日期筛选、重采样等高级时间序列分析。

## 核心参数详解

```python
pandas.to_datetime(
    arg,                        # 待转换的日期时间数据（支持字符串、数字、列表、Series 等）
    errors,                     # 解析遇到无效值时的错误处理策略
    dayfirst,                   # 解析时是否优先将第一个数字识别为“日”
    yearfirst,                  # 解析时是否优先将第一个数字识别为“年”
    utc,                        # 是否将解析结果强制转换为 UTC 时区
    format,                     # 自定义输入字符串的日期解析格式
    exact,                      # 要求输入字符串是否与指定的 format 格式完全匹配
    unit,                       # 指定数值型时间戳的时间单位（如秒、毫秒等）
    origin,                     # 设定将数字转换为日期时的基准起始时间
    cache,                      # 是否缓存解析结果以提升重复日期的处理性能
)
```

| 参数                    | 作用说明                                                     |
| ----------------------- | ------------------------------------------------------------ |
| `arg`                   | 必需参数。<br />需要转换的对象，可以是单个日期字符串、列表、数组或 Pandas Series。 |
| `format`                | 指定输入字符串的日期时间格式（如 `'%Y-%m-%d'`）。<br />指定格式可以大幅加快解析速度。 |
| `errors`                | 遇到无法解析的非法日期时的处理策略。<br />`'raise'`（默认，抛出异常）<br />`'coerce'`（转为 NaT 缺失值）<br />`'ignore'`（返回原始值）。 |
| `unit`                  | 当输入是数值型时间戳时，指定其时间单位。<br /> `'s'`（秒）、<br />`'ms'`（毫秒）、<br />`'D'`（天）等。 |
| `dayfirst`              | 默认为 `False`。<br />若设为 `True`，解析时会将日放在月前面（适用于 `dd/mm/yyyy` 格式）。 |
| `utc`                   | 默认为 `None`。<br />若设为 `True`，会将结果统一转换为 UTC（世界协调时间）。 |
| `infer_datetime_format` | 默认为 `False`。<br />若设为 `True`，Pandas 会尝试自动推断第一个非空元素的格式，以加速处理。 |

## 常见用法与实战示例

### 转换单个字符串或列表

Pandas 能够自动识别常见的日期格式。

```python
import pandas as pd

# 转换单个字符串
date = pd.to_datetime('2023-01-01')
print(date)  # 输出: 2023-01-01 00:00:00

# 转换列表
dates = pd.to_datetime(['2023-01-01', '2023-02-01'])
print(dates) 
# 输出: DatetimeIndex(['2023-01-01', '2023-02-01'], dtype='datetime64[ns]', freq=None)
```

### 转换 DataFrame 中的某一列

这是数据清洗中最常见的场景，直接覆盖原列即可。

```python
df['date'] = pd.to_datetime(df['date'])
```

### 处理非标准格式（使用 format）

如果日期字符串是 `dd/mm/yyyy` 或其他特殊格式，需要手动指定格式以避免解析错误。

```python
# 字符串为 01/02/2023，指定格式为 日/月/年
date = pd.to_datetime('01/02/2023', format='%d/%m/%Y')
print(date)  # 输出: 2023-02-01 00:00:00
```

### 处理时间戳（使用 unit）

当数据是 Unix 时间戳（整数或浮点数）时，必须配合 `unit` 参数。

```python
# 1626345600 代表以秒为单位的时间戳
date = pd.to_datetime(1626345600, unit='s')
print(date)  # 输出: 2021-07-15 00:00:00
```

### 容错处理（使用 errors）

如果数据中混杂了脏数据（例如 `'2023-02-30'` 这种不存在的日期），使用 `errors='coerce'` 可以将其安全地转换为 `NaT`（Not a Time，即时间类型的缺失值），防止程序报错中断。

```python
date = pd.to_datetime('2023-02-30', errors='coerce')
print(date)  # 输出: NaT
```

## 常用格式代码速查

在使用 `format` 参数时，以下代码最为常用：

- `%Y`：四位数年份（如 2023）
- `%m`：两位数月份（01-12）
- `%d`：两位数日期（01-31）
- `%H`：24小时制的小时数
- `%M`：分钟数
- `%S`：秒数

# `iterrows`

`pd.DataFrame.iterrows()` 是 Pandas 中用于逐行遍历 DataFrame 的常用方法。它返回一个生成器（迭代器），在每次迭代时产生一个包含行索引和行数据（Series对象）的元组。

> 把每一行的数据转化为一个 `Series`，相当于对行进行了转置。

## 使用格式

```python
# 基本遍历格式
for index, row in df.iterrows():  # index: 获取当前行的索引标签; row: 获取当前行的数据（以 Pandas Series 对象形式返回）
    print(index, row['列名'])     # 通过 Series 的键值对方式访问具体列的数据
```

## 参数与特性详解

需要特别说明的是，`iterrows()` 本身是一个无参数的方法（即括号内不需要传入任何参数）。下表总结了该方法返回的迭代器元素及其相关特性：

| 元素/特性 | 类型        | 作用与说明                                                   |
| --------- | ----------- | ------------------------------------------------------------ |
| `index`   | 标量        | 返回 DataFrame 中当前行的索引标签。                          |
| `row`     | `pd.Series` | 返回包含当前行数据的 Series 对象。<br />可以通过 `row['列名']` 或 `row.列名` 来获取指定列的值。 |
| 返回类型  | 迭代器      | 该方法不会一次性加载所有数据到内存，而是按需逐行生成 `(index, Series)` 对。 |
| 数据类型  | 自动推断    | 由于每行被转换为 Series，Pandas 可能会根据行内的数据自动推断并改变原始列的数据类型（dtypes）。 |

## 性能与使用注意事项

虽然 `iterrows()` 使用非常方便，但由于它在每次迭代时都会创建一个新的 Series 对象，**内存和计算开销较大**，因此在处理大型数据集时性能较低。如果数据量较大且对性能有要求，建议优先使用 `itertuples()` 方法（返回命名元组，速度更快）或 Pandas 的向量化操作。此外，`iterrows()` 返回的是行的副本而非视图，因此在循环中直接修改 `row` 的值不会影响原始的 DataFrame。

# `itertuple`

`pd.DataFrame.itertuples()` 是 Pandas 中用于逐行遍历 DataFrame 的另一种方法。与 `iterrows()` 不同，它返回的是一个命名元组（namedtuple）的迭代器，因此性能显著更高。

## 使用格式

```python
# 基本遍历格式（默认返回命名元组）
for row in df.itertuples():  # row: 获取当前行的数据（以 NamedTuple 对象形式返回）
    print(row.Index, row.列名)  # 通过属性访问具体列的数据，速度比字典键值访问更快

# 进阶遍历格式（自定义参数）
for row in df.itertuples(index=False, name='CustomRow'):  # index: 控制是否包含索引; name: 自定义元组的名称
    print(row.列名)  # 如果 index=False，则元组中不包含索引字段
```

## 参数与特性详解

`itertuples()` 方法接受几个可选参数，用于控制返回元组的形式。下表详细说明了各个参数的作用及可选值：

| 参数/特性 | 类型            | 作用与可选值                                                 |
| --------- | --------------- | ------------------------------------------------------------ |
| `index`   | `bool`          | 默认为 `True`。<br />如果为 `True`，返回的元组中会包含索引作为第一个元素（属性名为 `Index`）；<br />如果为 `False`，则不包含索引。 |
| `name`    | `str` 或 `None` | 默认为 `'Pandas'`。<br />用于指定返回的命名元组（namedtuple）的类名。<br />如果设为 `None`，则返回普通的元组（tuple），此时只能通过下标（如 `row[0]`）访问数据。 |
| 返回类型  | 迭代器          | 返回一个生成器，按需逐行生成元组，内存占用极低。             |
| 数据类型  | 保持原样        | 与 `iterrows()` 不同，`itertuples()` **不会**将每行强制转换为 Series，<br />因此能够完美保留原始列的数据类型（dtypes），避免了类型推断的开销。 |

## 性能与使用建议

在处理较大数据集时，`itertuples()` 的速度通常比 `iterrows()` 快数倍甚至数十倍。这是因为创建轻量级的元组比创建复杂的 Pandas Series 对象要快得多，且通过属性（如 `row.列名`）访问数据的速度也远快于 Series 的键值对访问（`row['列名']`）。如果你需要在循环中逐行处理数据且对性能有要求，`itertuples()` 是比 `iterrows()` 更优的选择。当然，如果可能，尽量使用 Pandas 内置的向量化操作（如 `apply` 或直接数组运算）依然是最高效的做法。

# `to_frame`

在 Pandas 中，`to_frame()` 方法的核心作用是将一个一维的 **Series** 数据结构，直接转换为一个二维的 **DataFrame**（数据框）。

## 核心作用与语法

`Series` 类似于带标签的一维数组，而 `DataFrame` 类似于二维表格。当你需要将一列数据变成表格格式，以便进行更复杂的合并（`merge`）、数据透视或可视化操作时，就需要用到这个方法。

其基本语法如下：

```python
Series.to_frame(name=None)
```

- `name`：用于指定转换后 DataFrame 的列名。如果不设置，默认列名通常为 `0` 或者保留原 Series 的名称。

## 代码演示

假设我们有一个关于城市名称的 Series：

```python
import pandas as pd

# 创建一个 Series
s = pd.Series(['杭州', '宁波', '嘉兴', '湖州'], name='城市')
```

**场景一：直接转换（默认列名）**

```python
df = s.to_frame()
print(df)
# 输出：
#      城市
# 0    杭州
# 1    宁波
# 2    嘉兴
# 3    湖州
```

**场景二：指定新列名**

```python
df_custom = s.to_frame(name='目标城市')
print(df_custom)
# 输出：
#   目标城市
# 0    杭州
# 1    宁波
# 2    嘉兴
# 3    湖州
```

## 将索引变成一列

`to_frame()` 方法默认会将原 Series 的索引（index）作为新 `DataFrame` 的行索引保留。如果你希望把索引也提取出来，变成 DataFrame 中的普通数据列，可以配合 `reset_index()` 方法使用：

```python
# 将索引转化为普通数据列
df_reset = s.reset_index() 
```

## 方法对比总结

在 Pandas 中，将 Series 转为 DataFrame 还有 `pd.DataFrame(s)` 或通过构建字典 `pd.DataFrame({'列名': s.values})` 等方法。相比之下，`to_frame()` 的优势在于：

- **简洁直接**：它是 Series 对象自带的内置方法，单行代码即可完成转换。
- **链式调用友好**：非常适合在数据处理流水线中直接使用（例如 `df.groupby('A')['B'].sum().to_frame()`），无需跳出当前对象去调用外部构造函数。

# `get_dummies`

`pd.get_dummies()` 是 Pandas 库中一个非常实用的函数，主要用于实现**独热编码（One-Hot Encoding）**。它的核心作用是将分类变量（通常是字符串或类别类型）转换为虚拟变量（也称为哑变量或指示变量）。

##  核心作用与原理

在数据分析或机器学习建模中，算法通常无法直接处理文本分类数据。`get_dummies` 会将**分类变量**的每个不同取值拆分为一个新的二进制列（0或1）：

- 如果原始数据属于该类别，对应的新列取值为 **1**。
- 如果不属于该类别，对应的新列取值为 **0**。

## 常用参数详解

```python
pandas.get_dummies(
    data,              # 待转换的输入数据（可以是 Series 或 DataFrame）
    prefix=None,       # 为生成的新列名添加的前缀字符串（或前缀列表）
    prefix_sep='_',    # 前缀与原始列名之间的分隔符（默认为下划线）
    dummy_na=False,    # 是否为缺失值（NaN）单独生成一列虚拟变量
    columns=None,      # 指定需要转换的列名列表（默认转换所有非数值列）
    drop_first=False,  # 是否删除第一个类别列（设为True可避免多重共线性）
    dtype=None,        # 指定生成的虚拟变量列的数据类型（如 np.uint8 以节省内存）
    sparse=False,	   # 是否使用稀疏矩阵表示结果
)
```

| 参数         | 作用说明                                                     |
| ------------ | ------------------------------------------------------------ |
| `data`       | 待转换的数据，可以是 Series、DataFrame 或数组。              |
| `columns`    | 指定需要转换的列名列表。如果不指定，默认会对所有非数值列进行转换。 |
| `prefix`     | 为生成的新列名添加前缀。                                     |
| `prefix_sep` | 设置前缀与原始列名之间的分隔符。                             |
| `drop_first` | 是否删除第一个虚拟变量列。默认为 `False`（生成 k 个类别列）。<br />若设为 `True`，则只生成 k-1 列，常用于线性回归模型中以避免多重共线性问题。 |
| `dummy_na`   | 是否为缺失值（NaN）单独创建一个虚拟变量列。默认为 `False`（NaN 会被直接丢弃或忽略）。<br />设为 `True` 才会多出一列。 |
| `sparse`     | 是否使用稀疏矩阵表示结果，在处理大规模数据时开启此参数可以有效节省内存空间。 |

## 使用实例

```python
import pandas as pd
df = pd.DataFrame({'color': ['red', 'blue', 'green', 'red']})

# 使用 get_dummies 进行独热编码
dummies_df = pd.get_dummies(df, columns=['color'], drop_first=True) 
# drop_first=True 用于避免多重共线性（虚拟变量陷阱），通常在线性模型中建议使用
print(dummies_df)
# 输出结果：
#         color_blue   color_green
# 0       False        False  (代表 red)
# 1        True        False  (代表 blue)
# 2       False         True  (代表 green)
# 3       False        False  (代表 red)
```



## 与 `map` 的区分

| 维度         | pandas.get_dummies()             | map()                                     |
| ------------ | -------------------------------- | ----------------------------------------- |
| 适用数据类型 | 无序分类数据（名义变量）         | 有序分类数据（序数变量）                  |
| 编码方式     | 独热编码（One-Hot Encoding）     | 标签编码 / 映射（Label Encoding）         |
| 维度变化     | 会增加维度（一个类别变成一列）   | 维度不变（原列替换为新列）                |
| 对模型的影响 | 避免引入虚假的顺序关系           | 会引入大小/顺序关系（模型会认为 2 > 1）   |
| 典型例子     | 城市（北京/上海）、颜色（红/蓝） | 衣服尺码（S/M/L）、学历（小学/中学/大学） |

## `drop_first` 参数说明

用一个包含“颜色”特征的简单数据集来演示。

假设有如下数据：

| 样本 | 颜色 |
| ---- | ---- |
| A    | 红   |
| B    | 绿   |
| C    | 蓝   |

### 默认情况 

`drop_first=False` 

这是最直观的转换方式。Pandas 会为每一个类别生成一列。

```python
import pandas as pd

df = pd.DataFrame({'颜色': ['红', '绿', '蓝']})
dummies_false = pd.get_dummies(df, columns=['颜色'], drop_first=False)
print(dummies_false)
```

**输出结果：**

|      | 颜色_红 | 颜色_绿 | 颜色_蓝 |
| ---- | ------- | ------- | ------- |
| 0    | 1       | 0       | 0       |
| 1    | 0       | 1       | 0       |
| 2    | 0       | 0       | 1       |

**问题所在（虚拟变量陷阱）**

如果把这三列放入线性回归模型，并且模型有一个截距项（Intercept，通常默认为1），会发现一个数学上的死循环：

`截距(1) = 颜色_红 + 颜色_绿 + 颜色_蓝` 

- 对于第一行：$1=1+0+0$ 
- 对于第二行：$1=0+1+0$ 

这意味着自变量之间存在**完全的线性关系**（多重共线性）。这会导致回归模型的矩阵无法求逆，或者计算出的系数极其不稳定，无法判断到底是“红色”影响了结果，还是“非绿色且非蓝色”影响了结果。

### 开启参数

`drop_first=True` 

这个参数会删掉排序后的第一个类别（这里是“红”），将其作为**基准组**。

```python
dummies_true = pd.get_dummies(df, columns=['颜色'], drop_first=True)
print(dummies_true)
```

**输出结果：**

|      | 颜色_绿 | 颜色_蓝 |
| ---- | ------- | ------- |
| 0    | 0       | 0       |
| 1    | 1       | 0       |
| 2    | 0       | 1       |

**好处**

现在只剩下两列。

- **第0行 (0, 0)**：既不是绿，也不是蓝 -> 隐含意思是**它是红色**。
- **第1行 (1, 0)**：是绿色。
- **第2行 (0, 1)**：是蓝色。

在这种设置下：

- “红色”的信息被**吸收**到了截距项中（当所有虚拟变量都为0时，就是基准组）。
- 模型计算出的“颜色_绿”的系数，代表的是**绿色相对于红色**的差异。
- 模型计算出的“颜色_蓝”的系数，代表的是**蓝色相对于红色**的差异。

这样就完美打破了线性相关性，保证了统计模型的数学严谨性。

### 总结对比

| 特性         | `drop_first=False` (默认)                         | `drop_first=True`                      |
| ------------ | ------------------------------------------------- | -------------------------------------- |
| **生成列数** | k 列，全保留。                                    | k - 1 列，少一列。                     |
| **信息量**   | 冗余 (存在完全共线性)。                           | 完整且独立 (无共线性)。                |
| **适用场景** | 树模型 (XGBoost, Random Forest)、神经网络。       | 线性回归、逻辑回归、统计学分析。       |
| **解释性**   | 每个系数代表该类别的绝对效应 (但在回归中不可靠)。 | 每个系数代表相对于**基准类别**的差异。 |

如果是在做**数据分析或传统统计建模**，请务必使用 `drop_first=True`；如果你是在做**深度学习或树模型**，用默认的 `False` 即可，因为算法本身能处理这种冗余。

# `shift`

`pandas` 中的 `shift` 是 `DataFrame` 和 `Series` 上用于按指定周期移动数据的方法，通过 `periods`、`freq`、`axis`、`fill_value`、`suffix` 等参数控制移动方向、时间频率、轴以及缺失值填充方式；它适合在时间序列分析中构造滞后特征、计算环比或同比变化、对齐前后行数据，也适合在普通表格中按行或按列平移数据，但不适合用来改变索引顺序或做真正的数据重采样。

## 使用格式

```python
DataFrame.shift(periods=1, freq=None, axis=0, fill_value=<no_default>, suffix=None)  # DataFrame 上的移位方法
Series.shift(periods=1, freq=None, axis=0, fill_value=None)                           # Series 上的移位方法
```

```py
periods,       # 移动周期数，可为整数或整数序列，正数通常向下/向右移，负数通常向上/向左移
freq=None,     # 时间频率偏移，用于时间索引场景，不改变数据位置而改变索引
axis=0,        # 移动轴，DataFrame 上可用 0 或 1，Series 上通常固定为 0
fill_value,    # 移动后新产生缺失位置的填充值，默认由数据类型决定
suffix=None,   # 当 periods 为序列时，用于生成移位后列名的后缀，仅 DataFrame 有效
```

## 参数说明


| 参数         | 作用                                                         | 类型与可选值                                                 | 示例                                                         |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `periods`    | 指定数据移动的周期数                                         | `int`、`Sequence[int]`；<br />可正、可负；<br />`DataFrame.shift` 中可传入整数序列 | `1`、<br />`-1`、<br />`[1, 2, 3]`                           |
| `freq`       | 指定时间索引的偏移频率；<br />传入后会移动索引而不重新对齐数据 | `DateOffset`、`tseries.offsets`、<br />`timedelta`、`str`、`None`；<br />也可使用 `"infer"` 自动推断 | `"D"`、<br />`"M"`、<br />`"B"`、<br />`"EOM"`、<br />`"infer"`、<br />`None` |
| `axis`       | 指定移动方向所在的轴                                         | `{0, 1, None}` 或 `{"index", "columns"}`；<br />`DataFrame` 默认通常为 `0`，<br />`Series` 上通常固定为 `0`。 | `0`、<br />`1`、<br />`"index"`、<br />`"columns"`、<br />`None` |
| `fill_value` | 移动后新产生缺失位置的填充值                                 | `object`；<br />默认依赖数据类型：数值型默认 `np.nan`，<br />时间型默认 `NaT`，<br />扩展类型默认 `self.dtype.na_value`。 | `0`、<br />`""`、<br />`np.nan`、<br />`"missing"`、<br />`None` |
| `suffix`     | 当 `periods` 为序列时，<br />附加到列名中的后缀文本          | `str`、`None`；<br />仅 `DataFrame.shift` 支持，<br />`Series.shift` 不使用。 | `"_lag"`、<br />`"_shift"`、<br />`None`                     |

`fill_value` 的默认值在不同 `pandas` 版本中可能略有差异，早期版本中常写作 `None`，较新版本中 `DataFrame.shift` 的默认值为 `<no_default>`，实际缺失值仍由数据类型决定。

## 简单示例

```python
import pandas as pd

df = pd.DataFrame({
    "date": pd.date_range("2026-09-25", periods=5, freq="D"),
    "value": [10, 20, 30, 40, 50]
}).set_index("date")

df["prev_value"] = df["value"].shift(1)
df["next_value"] = df["value"].shift(-1, fill_value=0)

print(df)
```

**输出类似**

```text
            value  prev_value  next_value
date
2026-09-25     10         NaN        20.0
2026-09-26     20        10.0        30.0
2026-09-27     30        20.0        40.0
2026-09-28     40        30.0        50.0
2026-09-29     50        40.0         0.0
```

这里 `shift(1)` 把数据向下移动一行，得到上一期的值；`shift(-1, fill_value=0)` 把数据向上移动一行，并用 `0` 填充最后产生的缺失值。

## `freq` 参数

`shift` 的 `freq` 参数可接受 `DateOffset`、`tseries.offsets`、`timedelta`、`str` 或 `None`；字符串形式采用 pandas 的“偏移别名”，且较新版本推荐优先使用 `ME`、`QE`、`YE`、`h`、`min`、`s`、`ms`、`us`、`ns` 等新式写法，旧式 `M`、`Q`、`A`、`H`、`T`、`S`、`L`、`U`、`N` 仍常见但部分已被标记为弃用。

| 别名    | 含义                   | 类型与可选值                                         | 示例                        |
| ------- | ---------------------- | ---------------------------------------------------- | --------------------------- |

| `B`     | 工作日                 | `str`                                                | `"B"`、`"3B"`               |
| `C`     | 自定义工作日           | `str`                                                | `"C"`                       |
| `W`     | 周                     | `str`                                                | `"W"`、`"W-MON"`、`"W-SUN"` |
| `ME`    | 自然月末               | `str`；新式写法，替代旧式 `M`                        | `"ME"`、`"2ME"`             |
| `MS`    | 自然月初               | `str`                                                | `"MS"`、`"3MS"`             |
| `BME`   | 工作日月末             | `str`；新式写法，替代旧式 `BM`                       | `"BME"`                     |
| `BMS`   | 工作日月初             | `str`                                                | `"BMS"`                     |
| `CBME`  | 自定义工作日月末       | `str`；新式写法，替代旧式 `CBM`                      | `"CBME"`                    |
| `CBMS`  | 自定义工作日月初       | `str`                                                | `"CBMS"`                    |
| `SME`   | 半月月末               | `str`；新式写法，替代旧式 `SM`                       | `"SME"`                     |
| `SMS`   | 半月月初               | `str`                                                | `"SMS"`                     |
| `QE`    | 自然季末               | `str`；新式写法，替代旧式 `Q`                        | `"QE"`                      |
| `QS`    | 自然季初               | `str`                                                | `"QS"`                      |

| `None`  | 不移动索引，只移动数据 | `NoneType`                                           | `None`                      |

简单示例：

```python
import pandas as pd

df = pd.DataFrame(
    {"value": [10, 20, 30]},
    index=pd.date_range("2026-09-25", periods=3, freq="D"),
)

# 按时间索引向后移动 1 天，数据不重排
df.shift(1, freq="D")

# 按时间索引向前移动 2 天
df.shift(-2, freq="2D")

# 自动推断索引频率后移动
df.shift(1, freq="infer")
```

如果索引不是时间类型，传入 `freq` 通常会报错；如果索引没有固定频率，`freq="infer"` 也会报错。
