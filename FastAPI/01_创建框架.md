# FastAPI 类介绍

`FastAPI` 类是整个 FastAPI 框架的核心入口与应用程序对象，通过实例化该类可以创建一个 Web 应用，用于定义路由、配置中间件、设置全局依赖及生成 OpenAPI 文档；通常在项目的主入口文件（如 `main.py`）中创建该实例，并在整个开发过程中通过它来组织和配置所有的 API 接口与全局功能。

## 创建对象时的格式

```python
app = FastAPI(
    *,  # 强制后续参数必须使用关键字传参
    debug=False,  # 是否开启调试模式，错误时返回详细跟踪信息
    routes=None,  # 自定义路由列表（通常不建议直接使用）
    title="FastAPI",  # API 的标题，显示在自动生成的文档中
    summary=None,  # API 的简短摘要，显示在文档中
    description="",  # API 的详细描述，支持 Markdown 格式
    version="0.1.0",  # API 的版本号（非 FastAPI 框架版本）
    openapi_url="/openapi.json",  # OpenAPI 架构的 URL，设为 None 可禁用文档
    openapi_tags=None,  # 用于文档的 OpenAPI 标签列表，便于对接口分组
    servers=None,  # 服务器列表，描述 API 部署的地址
    dependencies=None,  # 全局依赖项列表，对所有路由生效
    default_response_class=Default(JSONResponse),  # 默认的响应类
    redirect_slashes=True,  # 是否自动重定向带或不带尾部斜杠的路径
    docs_url="/docs",  # Swagger UI 文档的路径，设为 None 可禁用
    redoc_url="/redoc",  # ReDoc 文档的路径，设为 None 可禁用
    swagger_ui_oauth2_redirect_url="/docs/oauth2-redirect",  # Swagger UI 的 OAuth2 重定向 URL
    swagger_ui_init_oauth=None,  # Swagger UI 初始化 OAuth2 的配置字典
    middleware=None,  # 中间件列表
    exception_handlers=None,  # 自定义异常处理器字典
    on_startup=None,  # 应用启动时执行的回调函数列表
    on_shutdown=None,  # 应用关闭时执行的回调函数列表
    lifespan=None,  # 上下文管理器，用于处理应用启动和关闭的生命周期事件
    terms_of_service=None,  # 服务条款的 URL，显示在文档中
    contact=None,  # 联系人信息字典（包含 name、url、email）
    license_info=None,  # 许可证信息字典（包含 name、url）
    openapi_prefix="",  # OpenAPI 的前缀路径（已弃用，建议使用 root_path）
    root_path="",  # 应用挂载在反向代理后的根路径
    root_path_in_servers=True,  # 是否在生成的服务器 URL 中包含 root_path
    responses=None,  # 全局额外的响应定义，合并到 OpenAPI 文档中
    callbacks=None,  # 全局回调定义
    webhooks=None,  # 全局 Webhooks 定义
    deprecated=None,  # 是否将整个 API 标记为已弃用
    include_in_schema=True,  # 是否将路由包含在 OpenAPI 架构中
    swagger_ui_parameters=None,  # 传递给 Swagger UI 的额外配置参数
    generate_unique_id_function=Default(generate_unique_id),  # 生成操作唯一 ID 的函数
    separate_input_output_schemas=True,  # 是否为输入和输出生成独立的 OpenAPI 架构
    openapi_external_docs=None,  # 外部文档链接字典（包含 url、description）
    strict_content_type=True,  # 是否严格检查请求的 Content-Type 头
    **extra  # 允许传入额外的键值对，会作为自定义元数据添加到 OpenAPI 架构中
)
```

## 参数详细说明

| 参数名                           | 作用说明                                 | 常见可选值或类型                                     |
| -------------------------------- | ---------------------------------------- | ---------------------------------------------------- |
| `debug`                          | 控制是否返回调试跟踪信息                 | `True`，`False`（默认）                              |
| `routes`                         | 传入预定义的路由列表                     | `list[BaseRoute]`，`None`（默认）                    |
| `title`                          | 设置 API 文档的标题                      | 字符串，如 `"我的API"`（默认 `"FastAPI"`）           |
| `summary`                        | 设置 API 文档的简短摘要                  | 字符串，`None`（默认）                               |
| `description`                    | 设置 API 文档的详细描述，支持 Markdown   | 字符串，`""`（默认）                                 |
| `version`                        | 设置当前 API 的业务版本号                | 字符串，如 `"1.0.0"`（默认 `"0.1.0"`）               |
| `openapi_url`                    | 指定 OpenAPI JSON 架构的访问路径         | 字符串，如 `"/openapi.json"`（默认），`None`（禁用） |
| `openapi_tags`                   | 为接口分组并添加描述                     | 字典列表，`None`（默认）                             |
| `servers`                        | 声明 API 的服务器地址列表                | 字典列表，`None`（默认）                             |
| `dependencies`                   | 声明全局依赖项，所有路由执行前都会触发   | 依赖项列表，`None`（默认）                           |
| `default_response_class`         | 设置全局默认的响应类                     | `JSONResponse`（默认），`HTMLResponse` 等            |
| `redirect_slashes`               | 自动处理路径末尾斜杠的重定向             | `True`（默认），`False`                              |
| `docs_url`                       | Swagger UI 交互式文档的访问路径          | 字符串，如 `"/docs"`（默认），`None`（禁用）         |
| `redoc_url`                      | ReDoc 文档的访问路径                     | 字符串，如 `"/redoc"`（默认），`None`（禁用）        |
| `swagger_ui_oauth2_redirect_url` | Swagger UI 的 OAuth2 重定向端点          | 字符串，`None`                                       |
| `swagger_ui_init_oauth`          | 初始化 Swagger UI 的 OAuth2 配置         | 字典，`None`（默认）                                 |
| `middleware`                     | 注册全局中间件                           | 中间件类列表，`None`（默认）                         |
| `exception_handlers`             | 注册全局异常处理函数                     | 字典，`None`（默认）                                 |
| `on_startup`                     | 应用启动时执行的函数列表                 | 函数列表，`None`（默认）                             |
| `on_shutdown`                    | 应用关闭时执行的函数列表                 | 函数列表，`None`（默认）                             |
| `lifespan`                       | 管理应用启动与关闭的上下文管理器         | 异步上下文管理器，`None`（默认）                     |
| `terms_of_service`               | 服务条款的 URL                           | 字符串，`None`（默认）                               |
| `contact`                        | API 联系人信息                           | 字典，`None`（默认）                                 |
| `license_info`                   | API 许可证信息                           | 字典，`None`（默认）                                 |
| `openapi_prefix`                 | OpenAPI 的前缀路径（已弃用）             | 字符串，`""`（默认）                                 |
| `root_path`                      | 应用挂载在反向代理后的根路径             | 字符串，`""`（默认）                                 |
| `root_path_in_servers`           | 是否在文档的服务器列表中拼接 `root_path` | `True`（默认），`False`                              |
| `responses`                      | 全局附加的响应状态码及模型               | 字典，`None`（默认）                                 |
| `callbacks`                      | 全局回调定义                             | 字典，`None`（默认）                                 |
| `webhooks`                       | 全局 Webhooks 定义                       | 字典，`None`（默认）                                 |
| `deprecated`                     | 标记整个 API 为已弃用状态                | `True`，`False`（默认）                              |
| `include_in_schema`              | 控制路由是否展示在 OpenAPI 文档中        | `True`（默认），`False`                              |
| `swagger_ui_parameters`          | 自定义 Swagger UI 的渲染参数             | 字典，`None`（默认）                                 |
| `generate_unique_id_function`    | 自定义生成路由唯一 ID 的逻辑             | 可调用对象，默认生成函数                             |
| `separate_input_output_schemas`  | 分离请求体和响应体的 OpenAPI 架构        | `True`（默认），`False`                              |
| `openapi_external_docs`          | 指向外部文档的链接                       | 字典，`None`（默认）                                 |
| `strict_content_type`            | 严格校验请求头中的 Content-Type          | `True`（默认），`False`                              |
| `**extra`                        | 传入任意额外的自定义元数据               | 任意键值对                                           |

## 常用属性

| 属性名                     | 说明                                |
| -------------------------- | ----------------------------------- |
| `app.title`                | 获取或修改当前 API 的标题           |
| `app.version`              | 获取或修改当前 API 的版本号         |
| `app.description`          | 获取或修改当前 API 的描述信息       |
| `app.routes`               | 获取当前应用注册的所有路由列表      |
| `app.middleware_stack`     | 获取应用构建的中间件处理栈          |
| `app.openapi_schema`       | 获取生成的 OpenAPI 架构字典（缓存） |
| `app.dependency_overrides` | 用于测试时覆盖依赖项的字典          |

## 常用方法

| 方法名                    | 说明                                                         |
| ------------------------- | ------------------------------------------------------------ |
| `app.get()`               | 注册处理 HTTP GET 请求的路由                                 |
| `app.post()`              | 注册处理 HTTP POST 请求的路由                                |
| `app.put()`               | 注册处理 HTTP PUT 请求的路由                                 |
| `app.delete()`            | 注册处理 HTTP DELETE 请求的路由                              |
| `app.patch()`             | 注册处理 HTTP PATCH 请求的路由                               |
| `app.include_router()`    | 将 `APIRouter` 实例挂载到当前应用                            |
| `app.add_middleware()`    | 动态向应用添加中间件                                         |
| `app.exception_handler()` | 装饰器，用于注册自定义异常处理函数                           |
| `app.middleware()`        | 装饰器，用于注册 HTTP 中间件                                 |
| `app.on_event()`          | 注册启动（`"startup"`）或关闭（`"shutdown"`）事件（已逐渐被 `lifespan` 取代） |
| `app.openapi()`           | 生成并返回 OpenAPI 架构字典                                  |
| `app.api_route()`         | 支持配置路由函数使用不同的 HTTP 请求方法，传入 `methods` 参数 |
| `app.add_api_route()`     | 为某个路由添加请求方法或者新建一个路由，需传入 `endpoint` 参数（视图函数） |

# Debug 模式

FastAPI 类中内置了一个 Debug（调试）功能。通过它，人们可以实现类似使用 Flask 框架时再网页中看到错误堆栈信息明细的功能。

通过参数 `debug=True` 开启功能。

如果开启了全局异常处理，则不要开启调试模式，不然全局异常处理会失效。

# 交互式文档

FastAPI 的可交互式文档是框架基于代码中的类型注解、Pydantic 模型和路由定义，自动生成的一套符合 OpenAPI 标准的在线 API 说明页面。该文档无需手动编写或维护，能够随代码变更实时同步更新，默认提供 Swagger UI 和 ReDoc 两种界面，并附带原始的 OpenAPI JSON 规范文件。

- 在线调试接口

  无需借助 Postman 等外部工具，直接在浏览器中填写参数、发送请求并查看响应结果。

- 自动生成与同步

  文档内容完全由代码驱动，接口增删或参数修改后，文档自动更新，杜绝文档与代码不一致的问题。

- 降低对接成本

  为前端开发者或第三方调用方提供清晰的接口说明，包含请求路径、参数类型、请求体结构、响应模型及状态码等信息。

- 支持客户端代码生成

  基于 OpenAPI 规范，可利用工具自动生成多种语言的客户端 SDK。

- 展示认证机制

  若接口配置了 OAuth2、JWT 或 API Key 等安全方案，文档中会自动展示对应的认证入口。

## 模式

1. Swagger UI

   是一个流行的开源项目，可以为 API 自动生成交互式文档，允许人们通过用户界面来测试和交互式地调用 API 路由。

   通过 `主机地址/docs#` 访问。

2. ReDoc

   提供了一个响应式地文档查看器。类似 Swagger UI，ReDoc 可以帮助用户快速地浏览、测试和理解 API 路由的工作方式。

   通过 `主机地址/redoc` 查看。

| 文档类型     | 默认路径        | 说明                                              |
| ------------ | --------------- | ------------------------------------------------- |
| Swagger UI   | `/docs`         | 可交互式界面，支持在线填写参数并执行请求。        |
| ReDoc        | `/redoc`        | 只读式文档，排版清晰，适合查阅和分享。            |
| OpenAPI JSON | `/openapi.json` | 原始的 OpenAPI 规范 JSON 文件，供第三方工具消费。 |

## 参数

FastAPI 可交互式文档的配置参数主要分为两类：一类用于在 `FastAPI` 实例化时设置全局文档元数据与访问路径；另一类用于在路由装饰器或函数内部设置单个接口的文档信息。

> 生产环境中，不建议开启交互式文档，直接把对应的 `docs_url` 等设置为 `None` 就行。

### 文档相关参数格式

#### 全局文档

```python
# 全局文档配置（在 FastAPI 实例化时传入）
app = FastAPI(
    title="API 标题",  # 文档中显示的 API 名称
    summary="API 简短摘要",  # 文档中显示的简短介绍
    description="API 详细描述",  # 文档中显示的详细说明，支持 Markdown 语法
    version="1.0.0",  # API 的业务版本号
    terms_of_service="http://example.com/terms/",  # 服务条款的 URL 地址
    contact={  # 联系人信息字典
        "name": "联系人姓名",  # 联系人或组织名称
        "url": "http://example.com/contact/",  # 联系人或组织的 URL
        "email": "email@example.com",  # 联系人的电子邮箱
    },
    license_info={  # 许可证信息字典
        "name": "Apache 2.0",  # 许可证名称
        "url": "https://www.apache.org/licenses/LICENSE-2.0.html",  # 许可证的 URL
    },
    openapi_url="/openapi.json",  # OpenAPI 规范 JSON 文件的访问路径，设为 None 可禁用文档
    docs_url="/docs",  # Swagger UI 交互式文档的访问路径，设为 None 可禁用
    redoc_url="/redoc",  # ReDoc 只读文档的访问路径，设为 None 可禁用
    swagger_ui_oauth2_redirect_url="/docs/oauth2-redirect",  # Swagger UI 的 OAuth2 重定向回调路径
    swagger_ui_init_oauth=None,  # 传递给 Swagger UI 的 OAuth2 初始化配置字典
    swagger_ui_parameters=None,  # 传递给 Swagger UI 的额外配置参数字典
    openapi_tags=None,  # 用于文档分组的标签列表，包含 name 和 description
    servers=None,  # 服务器地址列表，描述 API 的部署环境
    openapi_external_docs=None,  # 外部文档链接字典，包含 url 和 description,
    openapi_prefix="" # 配置访问 openapi_json.json 文件路径的前缀
)
```

#### 单个路由

```python
# 单个路由的文档配置（在路由装饰器中传入）
@app.get(
    "/items/{item_id}",
    summary="接口简短摘要",  # 接口在文档列表中的简短标题
    description="接口详细描述",  # 接口的详细说明，支持 Markdown 语法
    response_description="成功响应的描述",  # 对成功响应内容的文字说明
    tags=["标签名称"],  # 接口分组标签，文档中按此标签折叠归类
    deprecated=False,  # 是否标记该接口为已弃用，文档中会以删除线显示
    include_in_schema=True,  # 是否将该接口包含在 OpenAPI 文档中
    responses={  # 自定义额外响应状态码及描述
        404: {"description": "资源未找到"},  # 定义 404 状态码的说明
        500: {"description": "服务器内部错误"},  # 定义 500 状态码的说明
    },
)
async def read_item(item_id: int):
    """
    函数的文档字符串（Docstring）：
    若未在装饰器中设置 description 参数，此处的文本将作为接口的详细描述展示在文档中。
    """
    return {"item_id": item_id}
```

### 代码示例

```python
from fastapi import FastAPI

app = FastAPI(
    title="商品管理 API",
    description="用于管理商品库存的接口服务",
    version="1.0.0",
    contact={
        "name": "技术支持",
        "email": "support@example.com",
    },
    openapi_tags=[
        {"name": "商品管理", "description": "商品的增删改查操作"},
    ],
)

@app.get(
    "/items/{item_id}",
    summary="获取商品信息",
    description="根据商品 ID 获取商品的详细信息",
    response_description="商品信息对象",
    tags=["商品管理"],
    responses={
        404: {"description": "商品未找到"},
    },
)
async def read_item(item_id: int):
    """
    获取商品信息：
    - **item_id**：商品的唯一标识符
    """
    return {"item_id": item_id}
```

# 全局 routes 参数

`FastAPI` 的全局 `routes` 参数是 `FastAPI` 类在实例化时支持的一个可选参数，用于在创建应用实例的同时传入一个预定义的路由列表；该参数通常用于需要批量导入路由、从外部配置加载路由或兼容 Starlette 原生路由定义的场景。但在 FastAPI 的主流开发规范中，更推荐使用装饰器或 `APIRouter` 来注册路由。

> 允许在创建 `FastAPI` 应用实例的那一瞬间，直接传入一批已经定义好的路由对象，而不是在实例化之后再去一个个添加。

## 使用格式

```python
from fastapi import FastAPI
from fastapi.routing import APIRoute

app = FastAPI(
    routes=[  # 传入预定义的路由对象列表
        APIRoute(
            path="/example",  # 路由的 URL 路径
            endpoint=example_handler,  # 处理该路由的函数
            methods=["GET"],  # 允许的 HTTP 请求方法列表
        ),
    ],
)
```

## 参数详细说明

| 参数名   | 作用说明                                           | 常见可选值或类型                  |
| -------- | -------------------------------------------------- | --------------------------------- |
| `routes` | 传入预定义的路由对象列表，在应用初始化时一次性注册 | `list[BaseRoute]`，`None`（默认） |

1. 兼容 Starlette 原生代码

   `FastAPI` 类继承自 `Starlette` 类。`routes` 参数是 `Starlette` 原生支持的参数。如果有一段纯 `Starlette` 的代码，或者从 `Starlette` 迁移到 `FastAPI`，这个参数可以保证原有的路由定义方式依然有效，无需修改代码。

2. 从外部配置/数据库动态加载路由

   在一些极端的动态系统中，路由可能不是写死在代码里的，而是存储在数据库或配置文件中。程序启动时，可以从外部读取配置，动态生成一个路由列表，然后通过 `routes` 参数一次性注入到应用中。

3. 框架内部的底层机制

   `FastAPI` 框架在内部处理 `APIRouter` 或装饰器注册的路由时，底层也是将它们收集到一个列表中，最终传递给 `Starlette` 基类。`routes` 参数是这个底层机制的一个直接入口。

## 常用属性与方法

| 属性/方法名                | 说明                                                         |
| -------------------------- | ------------------------------------------------------------ |
| `app.routes`               | 获取当前应用已注册的所有路由对象列表。                       |
| `APIRoute`                 | 用于构建路由对象的类，包含 `path`、`endpoint`、`methods` 等属性。 |
| `app.include_router()`     | 推荐的路由注册方式，用于挂载 `APIRouter` 实例。              |
| `app.get()` / `app.post()` | 推荐的装饰器方式，用于逐个注册路由。                         |

# APIRuote 介绍

`APIRoute` 是 FastAPI 框架中用于表示单个具体 HTTP 路由节点的核心类；在开发中，通常无需直接实例化该类（而是通过 `@app.get()` 等装饰器或 `APIRouter` 隐式创建），但在需要对特定路由进行精细化控制（如自定义请求处理逻辑、修改 OpenAPI 元数据或实现高级中间件行为）时，可以直接实例化 `APIRoute` 并通过 `app.routes.append()` 或 `APIRouter` 的 `routes` 参数进行注册。

## 创建对象时的格式

```python
from fastapi.routing import APIRoute

route = APIRoute(
    path="/items/{item_id}",  # 路由的 URL 路径，支持路径参数
    endpoint=read_item,  # 处理该路由的视图函数或协程
    methods=["GET"],  # 允许的 HTTP 请求方法列表
    name="read_item",  # 路由的名称，用于生成唯一 ID 和反向链接
    response_model=None,  # 响应数据的 Pydantic 模型，用于验证和文档生成
    status_code=200,  # 默认的成功响应状态码
    tags=None,  # OpenAPI 文档中的分组标签列表
    dependencies=None,  # 该路由专属的依赖项列表
    summary=None,  # OpenAPI 文档中的接口简短摘要
    description=None,  # OpenAPI 文档中的接口详细描述
    response_description="Successful Response",  # 成功响应的描述文本
    responses=None,  # 额外的响应状态码及描述字典
    deprecated=None,  # 是否标记该接口为已弃用
    operation_id=None,  # 自定义 OpenAPI 操作 ID，需保证全局唯一
    response_model_include=None,  # 响应模型中需要包含的字段集合
    response_model_exclude=None,  # 响应模型中需要排除的字段集合
    response_model_by_alias=True,  # 是否使用响应模型中的字段别名
    response_model_exclude_unset=False,  # 是否排除未显式设置的字段
    response_model_exclude_defaults=False,  # 是否排除具有默认值的字段
    response_model_exclude_none=False,  # 是否排除值为 None 的字段
    include_in_schema=True,  # 是否将该路由包含在 OpenAPI 文档中
    response_class=Default(JSONResponse),  # 默认的响应类
    callbacks=None,  # OpenAPI 回调定义列表
    openapi_extra=None,  # 额外的 OpenAPI 扩展元数据字典
    generate_unique_id_function=Default(generate_unique_id),  # 生成唯一 ID 的自定义函数
)
```

# 全局异常

`exception_handlers` 是 `FastAPI` 类在实例化时支持的一个可选参数，用于在创建应用实例的同时传入一个预定义的异常处理器映射字典。该参数的核心作用是实现**全局异常的统一拦截与标准化响应**，确保所有未被业务代码显式捕获的异常都能被转化为规范的 JSON 格式，避免向客户端暴露原始堆栈信息或导致服务崩溃。

通常在项目初始化阶段，需要集中配置全局错误处理策略、统一错误响应格式或集成日志监控时使用。

## 核心作用

- 统一错误响应格式

  将各种类型的异常（如参数校验错误、业务逻辑异常、系统未知异常）统一转化为结构一致的 JSON 响应，便于前端或调用方进行标准化解析。

- 防止敏感信息泄露

  拦截未处理的系统异常，避免将数据库密码、文件路径、代码堆栈等敏感信息直接暴露给客户端，提升应用安全性。

- 集中化错误处理

  将错误处理逻辑从具体的路由函数中抽离，使业务代码专注于核心逻辑，提升代码的可维护性与整洁度。

- 集成日志与监控

  在全局异常处理器中统一接入日志记录系统（如 Sentry、Loguru），实现错误的自动捕获、告警与链路追踪。

## 使用方式

`exception_handlers` 参数接收一个字典，字典的键（Key）为异常类（如 `Exception`、`HTTPException` 或自定义异常类），值（Value）为对应的异步处理函数。

### 定义异常处理函数

处理函数必须接收两个参数：`request`（当前请求对象）和 `exc`（捕获到的异常实例），并返回一个 `Response` 对象（通常为 `JSONResponse`）。

> 参数位置必须是 `request` 在前。

### 在实例化时传入字典

将异常类与处理函数的映射关系作为字典传入 `FastAPI` 构造函数。

## 代码示例

```python
from fastapi import FastAPI, HTTPException, Request
from fastapi.responses import JSONResponse
from sqlalchemy.exc import IntegrityError

# 1. 定义处理 HTTPException 的函数
async def http_exception_handler(request: Request, exc: HTTPException):
    return JSONResponse(
        status_code=exc.status_code,
        content={"code": exc.status_code, "message": exc.detail}
    )

# 2. 定义处理数据库完整性错误的函数
async def integrity_error_handler(request: Request, exc: IntegrityError):
    return JSONResponse(
        status_code=400,
        content={"code": 400, "message": "数据冲突，请检查输入"}
    )

# 3. 定义兜底的全局异常处理函数
async def global_exception_handler(request: Request, exc: Exception):
    # 此处可集成日志记录，如 logger.exception(...)
    return JSONResponse(
        status_code=500,
        content={"code": 500, "message": "服务器内部错误"}
    )

# 4. 在创建应用时，通过 exception_handlers 参数一次性注册
app = FastAPI(
    title="异常处理示例",
    exception_handlers={
        HTTPException: http_exception_handler,
        IntegrityError: integrity_error_handler,
        Exception: global_exception_handler,  # 兜底处理器，捕获所有未处理异常
    }
)
```

## 注意事项

1. 注册顺序与继承链

   `exception_handlers` 字典中的异常匹配依赖于 Python 的 MRO（方法解析顺序）。若同时注册了父类异常（如 `Exception`）和子类异常（如 `HTTPException`），框架会优先匹配更具体的子类异常处理器。

2. 与装饰器方式的区别

   `exception_handlers` 参数属于“无侵入”的声明式注册，适合在应用启动时集中绑定；而 `@app.exception_handler()` 装饰器则适合在代码不同位置动态注册。两者功能等价，但参数方式逻辑更集中。

3. 覆盖默认行为

   传入自定义处理器会覆盖 FastAPI/Starlette 内置的默认异常处理逻辑（如默认的 404 或 422 响应格式）。若需在自定义逻辑中保留默认行为，可从 `fastapi.exception_handlers` 导入并调用原始处理函数。
