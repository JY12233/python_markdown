# 请求体参数

请求体参数（Request Body Parameters）是指客户端（如浏览器、前端应用）通过 HTTP 请求（通常是 POST、PUT、PATCH 方法）发送给服务器的数据内容。在 FastAPI 框架中，请求体参数通常以 JSON 格式传输，用于提交复杂的数据结构（如用户注册信息、商品详情等）。与路径参数和查询参数不同，请求体参数不体现在 URL 中，而是隐藏在请求的内部载荷中。

## 核心作用

1. 提交复杂数据

   支持传输嵌套对象、列表等复杂数据结构，突破了 URL 长度和格式的限制。

2. 数据校验与转换

   结合 Pydantic 模型，自动对传入的 JSON 数据进行类型校验、格式验证及数据转换。

3. 自动化文档生成

   基于数据模型，自动生成符合 OpenAPI 规范的请求体 Schema，并在交互式文档中展示。

4. 编辑器智能提示

   为开发者提供完美的代码自动补全和类型检查，提升开发效率与代码质量。

## 使用方式

在 FastAPI 中，处理请求体参数的标准且推荐的方式是使用 Pydantic 模型。

### 定义数据模型

创建一个继承自 `pydantic.BaseModel` 的类，使用标准的 Python 类型提示来定义数据的结构和字段。

### 声明路径操作函数参数

在路径操作函数中，将定义好的 Pydantic 模型作为参数的类型提示。FastAPI 会自动识别该参数为请求体参数。

### 自动解析与校验

当请求到达时，FastAPI 会执行以下操作：

1. 读取请求体中的 JSON 数据。
2. 将 JSON 数据转换为对应的 Python 数据类型。
3. 根据模型定义校验数据的有效性（如类型是否正确、是否缺少必填字段）。
4. 若校验失败，自动返回清晰的错误信息；若成功，则**将数据作为函数参数**传入。

## 与其他参数的区别

| 对比维度     | 请求体参数               | 路径参数                    | 查询参数                      |
| ------------ | ------------------------ | --------------------------- | ----------------------------- |
| **数据来源** | HTTP 请求体（JSON）      | URL 路径（如 `/items/123`） | URL 查询字符串（如 `?q=foo`） |
| **声明方式** | Pydantic 模型类型        | 路径中的 `{变量名}`         | 函数参数（非路径参数）        |
| **适用场景** | 提交复杂数据（POST/PUT） | 定位特定资源                | 过滤、排序、分页              |
| **数据格式** | JSON 对象                | 字符串、整数等单值          | 字符串、整数等单值            |

## 混合使用场景

FastAPI 支持在同一个路径操作函数中无缝混合使用请求体参数、路径参数和查询参数。框架会根据参数的声明方式自动识别并提取数据：

1. 路径参数：函数参数名与路径中的 `{变量名}` 匹配。
2. 查询参数：函数参数为单一类型（如 `int`、`str`）且不在路径中。
3. 请求体参数：函数参数的类型声明为 Pydantic 模型。

## 代码示例

以下代码展示了如何在同一个视图函数中同时接收三种参数：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 1. 定义请求体数据模型
class Item(BaseModel):
    name: str
    price: float

# 2. 混合使用三种参数
@app.put("/items/{item_id}")
async def update_item(
    item_id: int,          # 路径参数：与路径中的 {item_id} 匹配
    q: str = None,         # 查询参数：单值类型且不在路径中，从 URL ? 后提取
    item: Item = None      # 请求体参数：Pydantic 模型类型，从 JSON 请求体提取
):
    return {
        "item_id": item_id,
        "q": q,
        "item": item
    }
```

# Schema

## 定义

在 FastAPI 及现代 Web 开发中，Schema（通常翻译为“模式”或“数据契约”）是对数据结构、字段类型及验证规则的严格定义。在 FastAPI 框架中，Schema 通常通过继承 Pydantic 库的 `BaseModel` 类来实现。

Schema 并非实际与数据库交互的 ORM 模型，而是专门用于在 API 层面定义请求体（Request Body）和响应体（Response Body）的数据接口形态。

当校验失败时，FastAPI 会返回 **`422 Unprocessable Entity`** 状态码。这个状态码专门用于表示“请求数据格式正确，但内容无法通过校验”。

## 核心作用

Schema 在 FastAPI 中扮演着“数据契约”的角色，其核心作用体现在以下四个维度：

1. 数据验证（Validation）

   自动校验客户端传入的数据是否符合预期的格式、类型和约束条件（如字符串长度、数值范围）。若数据无效，FastAPI 会自动返回清晰的错误提示。

2. 数据序列化与反序列化

   自动将 JSON 格式的请求数据转换为 Python 对象，并将 Python 对象转换为 JSON 格式的响应数据。

3. 自动生成 API 文档

   Schema 会被自动转换为 JSON Schema，并集成到 OpenAPI 规范中，从而在 Swagger UI 或 ReDoc 等交互式文档中直观展示接口的输入输出结构。

4. IDE 智能提示

   由于使用了标准的 Python 类型提示，开发环境（如 VS Code）能够提供精准的代码补全和类型检查，大幅减少拼写错误或类型错误。

## 使用流程

在 FastAPI 中使用 Schema 遵循“定义 -> 声明 -> 自动处理”的标准流程：

### 定义

通过继承 `pydantic.BaseModel` 定义数据结构。字段使用标准的 Python 类型注解，可选字段可通过默认值（如 `None`）声明。

```python
from pydantic import BaseModel, Field
from typing import Optional

class Item(BaseModel):
    name: str  # 必填字段，字符串类型
    description: Optional[str] = None  # 可选字段，默认为 None
    price: float = Field(..., gt=0, description="商品价格，必须大于0")  # 带约束的字段
    tax: Optional[float] = None
```

### 在路由中声明

将定义好的 Schema 类作为路径操作函数的参数类型注解（用于请求体）或返回类型注解（用于响应体）。

```python
from fastapi import FastAPI

app = FastAPI()

@app.post("/items/", response_model=Item)
async def create_item(item: Item):  # 将 Item 作为请求体参数
    return item
```

### 框架自动处理

仅需上述类型声明，FastAPI 会自动执行以下操作：

1. 读取请求体中的 JSON 数据。
2. 将数据转换为对应的 Python 类型。
3. 验证数据是否符合 `Item` 的定义。若不符合，返回 `422 Unprocessable Entity` 错误及详细错误信息。
4. 将函数返回的 Python 对象序列化为 JSON，并根据 `response_model` 过滤掉未定义的字段（保障数据安全）。
5. 将 Schema 信息注入到 OpenAPI 文档中。

## 与数据库模型的区别

在实际项目中，通常会将 Schema 与数据库（ORM Model）模型分离：

1. 数据库模型（ORM Model）

   负责定义数据库表的结构，直接与数据库进行交互。

2. Schema（Pydantic Model）

   负责定义 API 的数据接口。可以为同一个数据库模型定义多个不同的 Schema（例如 `UserCreate` 用于注册，`UserRead` 用于查询），从而实现关注点分离，并避免在响应中意外暴露密码等敏感信息。

## 高级用法

1. 字段约束

   使用 `Field` 函数可以添加丰富的约束条件，如 `gt`（大于）、`le`（小于等于）、`regex`（正则匹配）等。

2. 自定义验证器

   可以使用 `@validator` 装饰器编写复杂的自定义验证逻辑。

3. 配置类（Config）

   在 Schema 内部定义 `Config` 类，可以启用 `from_attributes=True`（Pydantic V2 语法），允许直接从 ORM 对象属性填充 Schema，简化数据库查询结果的转换。

# Body 函数

`Body` 是 FastAPI 框架中用于声明和校验 HTTP **请求体**（Request Body）中**单个值或额外参数**的函数。使用时需从 `fastapi` 模块导入，并将其作为路径操作函数中非 Pydantic 模型参数的默认值，当需要在请求体中接收除主模型之外的额外单值参数（如 `importance`），或需要对单个字段进行复杂的校验与元数据定义时，就可以使用该函数。

## 使用时的格式

```python
Body(
    default,  # 必填，参数的默认值（使用 ... 表示必填，或传入具体值/None 表示可选）
    *,  # 强制后续参数必须使用关键字传参
    embed=False,  # 可选，是否将单个参数嵌入到请求体字典中（默认为 False）
    gt=None,  # 可选，数值必须大于该值（Greater Than）
    ge=None,  # 可选，数值必须大于或等于该值（Greater than or Equal）
    lt=None,  # 可选，数值必须小于该值（Less Than）
    le=None,  # 可选，数值必须小于或等于该值（Less than or Equal）
    min_length=None,  # 可选，字符串或集合的最小长度
    max_length=None,  # 可选，字符串或集合的最大长度
    regex=None,  # 可选，字符串必须匹配的正则表达式
    title=None,  # 可选，参数的标题（用于生成 API 文档）
    description=None,  # 可选，参数的描述（用于生成 API 文档）
    alias=None,  # 可选，参数在请求体 JSON 中的别名
    deprecated=None,  # 可选，标记该参数是否已弃用
    **extra  # 可选，其他额外的元数据（会传递给 JSON Schema）
)
```

## 参数详解

| 参数名称      | 作用说明                               | 可选值或类型说明                                             |
| ------------- | -------------------------------------- | ------------------------------------------------------------ |
| `default`     | 指定参数的默认值，决定该参数是否必填。 | **任意值**：<br />`...`（必填）、<br />`None`（可选，默认为空）、<br />或具体的默认值（如 `10`、`"default"`） |
| `embed`       | 控制单个 `Body` 参数在请求体中的结构。 | **布尔值**：`False`（默认，参数作为顶层键）、<br />`True`（参数被包裹在与参数名同名的键中） |
| `gt`          | 数值校验：严格大于。                   | **整数**或**浮点数**：例如 `0`、`10.5`                       |
| `ge`          | 数值校验：大于或等于。                 | **整数**或**浮点数**：例如 `0`、`1`                          |
| `lt`          | 数值校验：严格小于。                   | **整数**或**浮点数**：例如 `100`                             |
| `le`          | 数值校验：小于或等于。                 | **整数**或**浮点数**：例如 `100`                             |
| `min_length`  | 长度校验：最小长度。                   | **整数**：例如 `1`、`10`                                     |
| `max_length`  | 长度校验：最大长度。                   | **整数**：例如 `50`、`1000`                                  |
| `regex`       | 字符串校验：正则表达式匹配。           | **字符串**：例如 `^[\w-]+$`                                  |
| `title`       | API 文档元数据：参数标题。             | **字符串**：例如 `"重要性等级"`                              |
| `description` | API 文档元数据：参数详细描述。         | **字符串**：例如 `"该值决定了任务的优先级"`                  |
| `alias`       | 请求体 JSON 中的字段别名。             | **字符串**：例如 `"item_importance"`                         |
| `deprecated`  | 标记参数为已弃用，文档中会显示删除线。 | **布尔值**：`True` 或 `False`（默认）                        |

## 简单代码示例

### 代码

以下示例展示了如何使用 `Body` 接收一个 Pydantic 模型之外的额外单值参数，并对其进行校验。

```python
from fastapi import FastAPI, Body
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

@app.put("/items/{item_id}")
async def update_item(
    item_id: int,  # 路径参数
    item: Item,  # Pydantic 模型（自动从请求体解析）
    importance: int = Body(  # 使用 Body 声明额外的单值参数
        ...,  # 必填参数
        gt=0,  # 必须大于 0
        le=5,  # 必须小于或等于 5
        title="重要性等级",  # API 文档标题
        description="任务的重要性，范围 1-5"  # API 文档描述
    )
):
    return {
        "item_id": item_id,
        "item": item,
        "importance": importance
    }
```

**请求体 JSON 示例：**

```json
{
    "name": "Foo",
    "price": 42.0,
    "importance": 3
}
```

### 处理解析

FastAPI 会根据路径操作函数中的参数声明，自动将请求体（JSON）中的字段“分流”到对应的变量中。具体过程如下：

1. Pydantic 模型接收对象

   FastAPI 发现 `item: Item` 参数是一个 Pydantic 模型，于是它会从请求体 JSON 中提取所有与 `Item` 模型字段匹配的数据（即 `name` 和 `price`），并将它们组装成一个 `Item` 对象赋值给 `item` 变量。

2. `Body` 接收单值

   FastAPI 发现 `importance: int = Body(...)` 参数使用了 `Body` 声明，于是它会从同一个请求体 JSON 中，单独提取出 `importance` 这个键对应的值，并赋值给 `importance` 变量。

FastAPI 内部的处理逻辑等价于：

```python
# 1. 从 JSON 中提取 name 和 price，构建 Item 对象
item = Item(name="Foo", price=42.0)

# 2. 从同一个 JSON 中提取 importance 的值
importance = 3
```

这种机制使得在同一个请求体中，既能传递结构化的复杂对象，又能传递简单的辅助参数，且两者互不干扰。

## `embed`参数

`Body` 中的 `embed` 参数，主要用于控制当路径操作函数中**仅有一个**请求体参数时，FastAPI 期望接收的 JSON 数据结构格式。

- 默认情况下（`embed=False`），如果函数只有一个 Pydantic 模型参数，FastAPI 期望请求体直接是该模型的 JSON 内容。

  ```json
  {
      "name": "张三",
      "age": 18
  }
  ```

- 当设置 `embed=True` 时，FastAPI 会期望请求体是一个包含该参数名作为键的嵌套 JSON 对象。

  ```json
  {
      "user": {
          "name": 张三,
          "age": 18
      }
  }
  ```

  `user` 是与视图函数的参数名相同。

### 参数格式与详解

```python
Body(
    default,  # 必填，参数的默认值（使用 ... 表示必填）
    *,  # 强制后续参数必须使用关键字传参
    embed=False,  # 可选，是否将请求体嵌入到以参数名命名的键中（默认为 False）
    # ... 其他校验参数（如 gt, le, min_length 等）
)
```

| 参数名称 | 作用说明                                 | 可选值或类型说明                                             |
| -------- | ---------------------------------------- | ------------------------------------------------------------ |
| `embed`  | 控制单个请求体参数在 JSON 中的结构层级。 | **布尔值**：`False`（默认，请求体直接为模型内容）、<br />`True`（请求体为嵌套结构，需包含参数名作为键） |

### 代码示例对比

以下示例展示了 `embed=False`（默认）与 `embed=True` 的区别：

#### 默认情况

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

# 只有一个 Pydantic 模型参数，默认 embed=False
@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    return {"item_id": item_id, "item": item}
```

**期望的请求体格式**（直接传递模型内容）：

```json
{
    "name": "Foo",
    "price": 42.0
}
```

#### 启用嵌入

```python
from fastapi import FastAPI, Body
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

# 设置 embed=True
@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item = Body(..., embed=True)):
    return {"item_id": item_id, "item": item}
```

**期望的请求体格式**（嵌套在参数名 `item` 中）：

```json
{
    "item": {
        "name": "Foo",
        "price": 42.0
    }
}
```

### 核心作用总结

`embed=True` 的主要作用是使 API 的请求体结构更加统一和清晰。当项目中既有单模型接口，又有包含额外单值参数（如 `importance`）的接口时，使用 `embed=True` 可以确保所有接口的请求体都是“键值对嵌套”的格式，避免客户端在调用不同接口时需要切换“直接传对象”和“传嵌套对象”两种模式。

# 多个请求体参数

当在路径操作函数中声明多个请求体参数（即多个 Pydantic 模型）时，**必须**将参数名作为键（Key）进行嵌套传递，而**不能**将所有字段直接展开在 JSON 的根层级。

## 核心识别机制

FastAPI 的参数识别逻辑如下：

1. 单个 Pydantic 模型参数

   框架默认期望请求体直接就是该模型的 JSON 内容。

2. 多个 Pydantic 模型参数

   当函数中存在两个或以上的 Pydantic 模型参数时，FastAPI 会意识到无法直接将一个 JSON 对象同时映射给两个模型。因此，框架会自动切换策略，**使用函数参数的变量名作为 JSON 的根键**，期望接收嵌套结构的数据。

## 数据结构对比

假设定义了 `Item` 和 `User` 两个模型，并在函数中同时接收：

```python
from pydantic import BaseModel


class Item(BaseModel):
    name: str
    price: float


class User(BaseModel):
    username: str
    full_name: str


@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, user: User):
    return {"item_id": item_id, "item": item, "user": user}
```

### 正确的传递方式

必须使用参数名 `item` 和 `user` 作为键（嵌套结构）：

```json
{
  "item": {
    "name": "Foo",
    "price": 42.0
  },
  "user": {
    "username": "dave",
    "full_name": "Dave Grohl"
  }
}
```

### 错误的传递方式

如果尝试将所有字段直接展开，FastAPI 将无法识别这些数据属于哪个模型，从而导致校验失败（展开结构）：

```json
{
  "name": "Foo",
  "price": 42.0,
  "username": "dave",
  "full_name": "Dave Grohl"
}
```

## 特殊需求

如果希望即使只有一个 Pydantic 模型参数时，也强制要求使用参数名作为键的嵌套结构，可以使用 `Body` 函数的 `embed=True` 参数：

```python
from fastapi import Body

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item = Body(embed=True)):
    return {"item_id": item_id, "item": item}
```

此时，即使只有一个 `item` 参数，前端也必须传递 `{"item": {...}}` 这种嵌套格式。

# 原生类型请求体解析

在 FastAPI 框架中，当路径操作函数直接使用 Python 原生类型（如 `list`、`dict`、`set`）作为参数时，若未进行显式声明，极易引发请求体解析歧义，导致服务端抛出 `AttributeError: 'str' object has no attribute 'read'` 异常。

理解该错误的底层机制并掌握 `Body()` 函数的正确用法，是构建健壮 API 的关键。

## 错误原因分析

该错误的核心在于 FastAPI 的依赖注入系统在处理非 Pydantic 模型参数时，错误地将 JSON 请求体推断为表单数据（Form Data）。

1. 触发条件

   在路径操作函数中直接使用 `list`、`dict`、`set` 等原生类型作为参数，且未使用 `Body()` 进行显式声明。

2. 解析歧义

   FastAPI 在处理复杂嵌套的原生类型时，可能会错误地期望接收 `application/x-www-form-urlencoded` 格式的表单数据，而非 `application/json` 格式的 JSON 数据。

3. 异常产生

   当 FastAPI 按表单数据逻辑解析时，会尝试调用每个字段的 `.read()` 方法来读取文件内容。然而，实际传入的 JSON 数据中的字段值是字符串（`str`），字符串对象不具备 `.read()` 方法，从而抛出 `AttributeError`。

## 解决方案

要彻底消除解析歧义，必须使用 `fastapi.Body` 函数明确告知框架：该参数应从 JSON 请求体中获取。

## 代码示例

```python
import uvicorn
from fastapi import FastAPI, Body

app = FastAPI(title="请求体不同类型")

@app.get("/")
def root():
    return {"index": "root"}

@app.post("/items")
def items(
    # 使用 Body() 明确指定这些参数来自 JSON 请求体
    # 不然会当作表单数据处理
    users: list[str] = Body(...),  # 声明为必填的字符串列表
    item: dict[str, str] = Body(...),  # 声明为必填的字典
    spec: list[dict[str, str]] = Body(...),  # 声明为必填的字典列表
    tags: set = Body(...),  # 声明为必填的集合
):
    return {
        "users": users,
        "item": item,
        "spec": spec,
        "tags": tags,
    }

if __name__ == "__main__":
    uvicorn.run(app)
```

## 开发规范

1. Pydantic 模型优先原则

   对于结构化的请求体数据，始终优先使用 Pydantic 的 `BaseModel`。这是 FastAPI 最标准、最推荐的做法，框架能自动、无误地识别并处理，完全避免解析歧义。

2. 原生类型显式声明原则

   当确实需要使用 `list`、`dict` 等原生类型作为请求体参数时，必须使用 `Body()` 函数进行显式声明，以强制框架按 JSON 格式解析。

3. 必填参数标识

   在 `Body(...)` 中，`...`（Ellipsis，省略号）表示该参数为必填项。若省略该参数或设置为具体默认值，则该参数变为可选。

# 大文件

`UploadFile` 是 FastAPI 框架中专门用于接收和处理客户端上传文件的类；该类通常在需要处理大文件上传、获取文件元数据（如文件名、内容类型）或进行异步文件操作时使用，通过将其作为路径操作函数的参数类型，框架会自动将上传的文件包装为 `UploadFile` 实例，提供异步读写方法并避免将整个文件加载到内存中。

> 有异步接口和文件的元数据。

## 创建对象时的格式

```python
from fastapi import UploadFile

upload_file = UploadFile(
    file,  # 标准的 Python 文件对象（BinaryIO），通常是请求中上传的文件流
    *,  # 强制后续参数必须使用关键字传参
    size=None,  # 文件的大小（以字节为单位），默认为 None
    filename=None,  # 原始文件名，默认为 None
    headers=None  # 请求的头部信息（Headers 对象），默认为 None
)
```

## 参数详细说明

| 参数名     | 作用说明                                                   | 常见可选值或类型     |
| ---------- | ---------------------------------------------------------- | -------------------- |
| `file`     | 传入标准的 Python 文件对象（BinaryIO），作为文件内容的载体 | 文件对象（BinaryIO） |
| `size`     | 指定文件的大小（以字节为单位），用于快速校验               | 整数, `None`         |
| `filename` | 指定上传文件的原始文件名                                   | 字符串, `None`       |
| `headers`  | 传入请求的头部信息，用于获取 Content-Type 等元数据         | Headers 对象, `None` |

## 常用属性

| 属性名         | 说明                                             |
| -------------- | ------------------------------------------------ |
| `file`         | 标准的 Python 文件对象（非异步），可用于同步操作 |
| `filename`     | 上传文件的原始文件名（字符串）                   |
| `size`         | 文件的大小（以字节为单位）                       |
| `headers`      | 请求的头部信息（Headers 对象）                   |
| `content_type` | 文件的内容类型（MIME 类型），从头部信息中提取    |

## 常用方法

| 方法名                | 说明                                                       |
| --------------------- | ---------------------------------------------------------- |
| `async read(size=-1)` | 异步读取文件内容，`size` 为读取的字节数（-1 表示读取全部） |
| `async write(data)`   | 异步向文件写入字节数据（通常不用于读取上传的文件）         |
| `async seek(offset)`  | 异步移动文件指针到指定位置                                 |
| `async close()`       | 异步关闭文件流，释放资源                                   |

## 代码使用示例

以下示例展示了如何使用 `UploadFile` 接收上传的文件，并读取其内容和元数据。

```python
from fastapi import FastAPI, UploadFile

app = FastAPI()

@app.post("/uploadfile/")
async def create_upload_file(file: UploadFile):
    # 1. 获取文件元数据
    filename = file.filename
    content_type = file.content_type
    
    # 2. 异步读取文件内容
    contents = await file.read()
    
    # 3. 处理文件（例如保存到磁盘）
    with open(f"./{filename}", "wb") as f:
        f.write(contents)
    
    return {
        "filename": filename,
        "content_type": content_type,
        "size": len(contents)
    }
```

### 核心优势

1. 内存友好

   对于大文件，`UploadFile` 会使用临时文件存储，避免将整个文件加载到内存中，防止内存溢出。

2. 元数据丰富

   自动提供文件名、内容类型等元数据，无需手动从请求头解析。

3. 异步支持

   提供异步读写方法，与 FastAPI 的异步架构完美契合，提升并发性能。

4. 资源管理

   提供 `close()` 方法，确保文件流在使用后正确关闭，避免资源泄漏。

## 注意事项

1. 依赖安装

   使用 `UploadFile` 前，必须安装 `python-multipart` 库（`pip install python-multipart`），否则无法解析文件上传数据。

2. 异步函数

   `UploadFile` 的 `read()`、`write()` 等方法都是异步的，必须在 `async def` 函数中使用 `await` 调用。

3. 资源释放

   在处理完文件后，建议显式调用 `await file.close()` 或使用异步上下文管理器，确保文件流被正确关闭。
