# 挂载介绍

在 FastAPI 中，“挂载（Mount）”是指在特定的 URL 路径下，添加一个完全“独立”的子应用程序或处理程序。该子程序将全权负责处理该路径及其所有子路径下的请求。

挂载机制的核心价值在于实现应用的模块化拆分与功能解耦，常用于托管静态文件、挂载独立的子 FastAPI 应用，或集成其他 WSGI 框架（如 Flask、Django）。

>**用一个比喻来帮助理解**
>
>可以把主应用想象成一座**总枢纽站**，而挂载的子应用则是枢纽站管理的各个**独立站台**。每个站台（子应用）都有自己的工作人员、时刻表和工作流程（独立的逻辑、路由和中间件）。总枢纽（主应用）只负责将乘客（请求）引导到正确的站台，而站台内部如何运作，总枢纽完全不过问。

## 核心作用

1. 静态文件

   托管将本地目录映射为特定的 URL 路径，使浏览器能够直接访问 CSS、JS、图片等静态资源。

2. 应用模块化拆分

   将大型应用拆分为多个拥有独立 OpenAPI 文档和独立路由的子应用，降低单文件复杂度。

3. 多框架共存

   允许在同一个服务中同时运行 FastAPI 与其他 Python Web 框架（如 Flask），便于渐进式迁移或功能整合。

4. 路径隔离

   挂载的子应用拥有独立的路径命名空间，避免不同模块间的路由冲突。

## 常见使用场景

### 挂载静态文件

这是最常见的挂载场景。通过 `StaticFiles` 类，将本地文件夹绑定到特定的 URL 前缀。

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()

# 将本地的 "static" 文件夹挂载到 "/static" 路径下
# 访问 /static/style.css 时，框架会自动返回 static/style.css 文件
app.mount("/static", StaticFiles(directory="static"), name="static")
```

### 挂载独立子应用

当需要两个完全独立的 FastAPI 应用（拥有各自的文档和路由）时，可以使用挂载。

```python
from fastapi import FastAPI

# 主应用
app = FastAPI()

@app.get("/")
def read_main():
    return {"message": "来自主应用"}

# 子应用
sub_app = FastAPI()

@sub_app.get("/items")
def read_sub_items():
    return {"message": "来自子应用"}

# 将子应用挂载到 /subapi 路径下
# 子应用的接口完整路径为 /subapi/items
# 子应用的独立文档位于 /subapi/docs
app.mount("/subapi", sub_app)
```

> 在主应用使用交互文档时，不会出现子应用的，必须要到挂载子应用的路径打开才可以。

### 挂载其他 WSGI 框架

通过 `WSGIMiddleware`，可以将 Flask 等传统同步框架挂载到 FastAPI 中。

```python
from fastapi import FastAPI
from fastapi.middleware.wsgi import WSGIMiddleware
from flask import Flask

flask_app = Flask(__name__)

@flask_app.route("/")
def flask_main():
    return "Hello from Flask!"

app = FastAPI()

# 将 Flask 应用挂载到 /flask 路径下
app.mount("/flask", WSGIMiddleware(flask_app))
```

## 挂载与路由包含

在 FastAPI 开发中，`app.mount()` 与 `app.include_router()` 是两个极易混淆的概念，其核心区别如下：

| 对比维度     | `app.mount()`                                                | `app.include_router()`                 |
| ------------ | ------------------------------------------------------------ | -------------------------------------- |
| **挂载对象** | 独立的 ASGI/WSGI 应用（如 `StaticFiles`、另一个 `FastAPI` 实例） | `APIRouter` 路由分组对象               |
| **独立性**   | 完全独立，拥有自己的中间件、异常处理和 OpenAPI 文档          | 非独立，共享主应用的配置、依赖和文档   |
| **文档生成** | 主应用的 `/docs` 不会包含挂载的子应用内容                    | 路由会被合并到主应用的 `/docs` 文档中  |
| **典型场景** | 托管静态文件、集成第三方框架、拆分微服务                     | 按业务模块（如用户、订单）拆分路由代码 |

## 注意事项

- 路径匹配优先级

  挂载的子应用会接管其前缀下的所有请求。如果主应用定义了与挂载路径冲突的路由，挂载的子应用会优先处理。

- 静态文件挂载位置

  通常建议将 `app.mount("/static", ...)` 放在所有路由定义之后，以避免意外拦截正常的 API 请求。

- 名称参数

  在挂载 `StaticFiles` 时，`name` 参数是可选的，但在需要在代码内部反向生成静态文件 URL 时非常有用。

# `mount` 函数

`app.mount` 是 FastAPI（继承自 Starlette）中用于将独立的子应用或处理程序绑定到特定 URL 路径的核心方法；该方法通过传入挂载路径、子应用实例及可选名称，使主应用在接收到匹配该路径的请求时，将控制权完全移交给子应用处理，通常在需要托管静态文件、拆分微服务模块或集成第三方 WSGI 框架时使用。

## 使用格式

```python
app.mount(
    path,  # 挂载的 URL 路径前缀（如 "/static" 或 "/admin"）
    app,   # 要挂载的子应用实例（如 StaticFiles、FastAPI 或 WSGIMiddleware 对象）
    name=None  # 子应用的内部名称，用于反向生成 URL（可选参数）
)
```

## 参数详细说明

| 参数名 | 作用说明                               | 常见可选值或类型                                             |
| ------ | -------------------------------------- | ------------------------------------------------------------ |
| `path` | 定义子应用接管的 URL 路径前缀          | 字符串，如 `"/static"`、`"/api/v1"`、`"/admin"`              |
| `app`  | 传入需要被挂载的独立应用或处理程序实例 | `StaticFiles`、`FastAPI`、`WSGIMiddleware` <br />等 ASGI/WSGI 应用 |
| `name` | 为挂载点指定一个内部标识名称           | 字符串，如 `"static"`、`"admin"`，默认为 `None`              |

## 代码示例

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()

# 将本地的 "static" 文件夹挂载到 "/static" 路径下
# 访问 /static/style.css 时，将由 StaticFiles 处理并返回对应文件
app.mount("/static", StaticFiles(directory="static"), name="static")

# 将一个独立的子应用挂载到 "/admin" 路径下
admin_app = FastAPI()

@admin_app.get("/")
def admin_home():
    return {"message": "管理后台首页"}

app.mount("/admin", admin_app, name="admin")
```

# 静态文件

`StaticFiles` 是 FastAPI（底层基于 Starlette）中专门用于托管静态文件（如 CSS、JavaScript、图片等）的 ASGI 应用类。

在实际开发中，该类通常不单独使用，而是作为参数传递给前面介绍的 `app.mount()` 方法，从而将本地的物理目录挂载到指定的 URL 路径上，通常在需要为前端提供资源文件或处理用户上传的媒体文件时使用。

## 静态文件介绍

静态文件是指存储在 Web 服务器上，无需经过服务器端程序编译、处理或数据库查询，即可直接加载到客户端浏览器显示的文件。常见的静态文件类型包括 CSS 样式表、JavaScript 脚本、图片（如 PNG、JPG）、字体文件、音频及视频文件等。与动态内容（如 API 接口返回的实时数据）不同，静态文件的内容在用户请求前已预先存在且固定，同一 URL 的访问通常返回相同内容。

1. 构建页面结构与样式

   HTML 文件提供页面骨架，CSS 文件控制视觉排版，JavaScript 文件实现前端交互逻辑，三者共同构成完整的网页体验。

2. 提升访问速度与性能

   静态文件无需服务器端进行复杂的逻辑计算或数据库查询，服务器可直接读取并返回文件，响应速度极快。

3. 减轻服务器负载

   将静态文件与动态 API 请求分离，避免大量资源请求占用后端应用服务器的计算资源，使其能专注于处理核心业务逻辑。

4. 支持 CDN 加速与缓存

   由于内容固定不变，静态文件非常适合部署在内容分发网络（CDN）上，并通过浏览器缓存机制（如设置 `Cache-Control`）减少重复下载，大幅降低网络延迟和带宽消耗。

## 创建对象时的格式

```python
from fastapi.staticfiles import StaticFiles

static_files_app = StaticFiles(
    *,  # 强制后续参数必须使用关键字传参
    directory=None,  # 指定包含静态文件的本地物理目录路径
    packages=None,  # 指定包含静态文件的 Python 包列表（用于从第三方库中提供静态文件）
    html=False,  # 是否开启 HTML 模式（开启后访问目录会自动查找并返回 index.html）
    check_dir=True,  # 是否在启动时检查目录是否存在，不存在则抛出异常
    follow_symlink=False  # 是否允许跟随符号链接（出于安全考虑，默认禁止）
)
```

## 参数说明

| 参数名           | 作用说明                               | 常见可选值或类型                                  |
| ---------------- | -------------------------------------- | ------------------------------------------------- |
| `directory`      | 指定静态文件所在的本地文件系统路径     | 字符串或 `Path` 对象，如 `"static"`、`"./assets"` |
| `packages`       | 指定需要从其中提取静态文件的 Python 包 | 字符串列表或元组列表，如 `["bootstrap4"]`、``     |
| `html`           | 控制是否启用 HTML 目录索引模式         | `True`，`False`（默认）                           |
| `check_dir`      | 控制是否在初始化时校验目录的合法性     | `True`（默认），`False`                           |
| `follow_symlink` | 控制是否允许访问符号链接指向的外部文件 | `True`，`False`（默认）                           |

### `directory`

> 本地物理目录路径。

1. 核心作用

   指定静态文件在服务器本地文件系统中的实际存储位置。当客户端发起请求时，框架会在这个指定的目录下查找对应的文件并返回。

2. 详细机制

   该参数接收一个字符串路径或 `Path` 对象。路径可以是相对路径（相对于项目启动目录）或绝对路径。如果指定的目录在本地文件系统中不存在，且 `check_dir` 参数为 `True`，程序在启动时会直接抛出 `RuntimeError` 异常。

3. 典型场景

   存放项目自定义的 CSS、JavaScript、图片等前端资源，例如 `directory="static"` 或 `directory="/var/www/assets"`。

### `packages`

> Python 包资源列表。

1. 核心作用

   允许直接从已安装的 Python 第三方包中提取并提供静态文件，而无需将文件手动复制到本地目录。

2. 详细机制

   该参数接收一个列表，列表中的元素可以是字符串或元组。

   - 字符串格式（如 `["bootstrap4"]`）

     框架会自动在该包的安装目录下寻找名为 `statics` 的子目录。

   - 元组格式（如 `[("bootstrap4", "static")]`）

     允许自定义包内静态文件所在的子目录名称（此处为 `static`）。

3. 典型场景

   当项目依赖某些自带前端资源的 Python 库（如 `bootstrap4`、`chainlit`）时，直接通过此参数挂载，避免手动拷贝文件，便于统一管理和升级。

### `html`

> HTML 目录索引模式。

1. 核心作用

   控制当客户端请求一个目录路径（而非具体文件）时，服务器的响应行为。

2. 详细机制

   - 当设置为 `False`（默认值）时，请求目录路径会返回 404 Not Found 错误。
   - 当设置为 `True` 时，框架会自动在该目录下查找 `index.html` 文件。如果找到，则将其作为响应返回；如果未找到，则返回 404 错误。

3. 典型场景

   托管单页面应用（SPA，如 Vue、React 的打包产物）或传统的多页面静态网站。开启此选项后，访问 `/admin/` 会自动返回 `/admin/index.html`。

### `check_dir`

> 启动时目录校验。

1. 核心作用

   控制在应用实例化时，是否强制检查 `directory` 参数指定的本地目录是否存在。

2. 详细机制

   - 当设置为 `True`（默认值）时，如果目录不存在，程序启动阶段就会立即报错并终止，防止运行时出现不可预知的文件读取错误。
   - 当设置为 `False` 时，即使目录不存在，程序也能正常启动。只有当实际请求到达该路径时，才会返回 404 错误。

3. 典型场景

   在容器化部署或动态生成目录的场景中，如果静态文件目录可能在运行时才由其他进程创建，可暂时设为 `False` 以避免启动失败。

### `follow_symlink`

> 符号链接跟随。

1. 核心作用

   控制服务器是否允许访问指向静态目录外部的符号链接（Symbolic Link）文件。

2. 详细机制

   - 当设置为 `False`（默认值）时，出于安全考虑，框架会严格限制文件访问范围。如果请求的路径包含指向目录外部的符号链接，服务器会拒绝访问并返回 404 错误，从而防止“目录遍历攻击”导致服务器敏感文件（如系统配置文件、源代码）泄露。
   - 当设置为 `True` 时，允许跟随符号链接读取外部文件。

3. 典型场景

   仅在本地开发环境中，当需要临时链接外部测试资源时使用。**在生产环境中，强烈建议保持默认的 `False` 状态以确保安全性。**

## 常用属性与方法

| 属性/方法名         | 说明                                                        |
| ------------------- | ----------------------------------------------------------- |
| `directory`         | 获取当前配置的静态文件物理目录路径                          |
| `packages`          | 获取当前配置的 Python 包列表                                |
| `html`              | 获取当前的 HTML 模式开关状态                                |
| `get_response()`    | 异步方法，根据请求路径返回对应的文件响应（底层核心方法）    |
| `lookup_path()`     | 根据请求路径在本地文件系统中查找对应的物理文件路径          |
| `is_not_modified()` | 根据请求头判断文件是否未修改，用于返回 304 状态码以优化缓存 |

## 代码示例

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()

# 1. 创建 StaticFiles 实例，指向本地的 "static" 文件夹
# 2. 通过 app.mount 将其挂载到 "/static" 路径下
# 此时访问 /static/style.css 就会返回 static/style.css 文件
app.mount("/static", StaticFiles(directory="static"), name="static")
```

> 一般，建议挂载的 URL 与 `direction` 相同。
>
> 假设挂载的是 `/static`，而 `direction="assets"`，那么有可能出问题。因为我们可能一瞬间就会想到访问 `/assets/photo.jpg`，但是实际的应该是 `/static/photo.jpg`。
>
> 它应该是访问 static 时去 assets 目录找对应的文件。
>
> 同理，在 html 中写 src 时，第一个 `/` 下的文件也要与这里的 URL 相同，这样才能正确的访问。因为我们挂载的是这个 URL，html 中肯定不能写另一个。

# 目录解析

在计算机文件系统与 Web 开发中，路径解析的基准点是理解资源加载的关键。路径通常分为“盘符目录（绝对路径）”与“工作目录（相对路径）”两种逻辑。两者的核心区别在于定位文件时的**参照系**不同。

## 核心概念定义

### 盘符目录

绝对路径，以操作系统根目录或磁盘驱动器为起点的完整路径。在 Windows 系统中，通常以盘符加冒号开头（如 `C:`、`D:`）；在类 Unix 系统（Linux、macOS）中，以根目录斜杠 `/` 开头。

> 无论当前程序运行在何处，绝对路径指向的物理位置永远固定不变。

### 工作目录

相对路径/当前目录，程序或脚本在运行时所在的默认目录（Current Working Directory, CWD）。相对路径是相对于这个目录进行解析的。

> 具有动态性。如果从不同的位置启动同一个程序，其工作目录可能会发生变化，导致相对路径指向不同的物理位置。

在 python 中，`.` 代表当前工作目录而不是文件所在目录 `__file__`。

## 路径解析机制对比

| 维度         | 盘符目录（绝对路径）                            | 工作目录（相对路径）                     |
| ------------ | ----------------------------------------------- | ---------------------------------------- |
| **起始基准** | 操作系统根目录或磁盘驱动器                      | 当前程序运行的工作目录                   |
| **典型格式** | `D:/projects/css/style.css` 或 `/usr/local/bin` | `./css/style.css` 或 `../assets/img.png` |
| **稳定性**   | 极高，不受运行环境影响                          | 较低，依赖于启动命令的执行位置           |
| **适用场景** | 系统级配置、跨目录的固定资源引用                | 项目内部资源引用、模块化代码             |

## Web 开发中的路径解析

在前端开发（如 HTML 引入 CSS）中，路径解析的逻辑会因打开方式的不同而发生本质变化，这也是导致“找不到文件”错误的常见原因。

### 本地直接打开

当直接双击 HTML 文件在浏览器中打开时，浏览器使用 `file://` 协议。

1. `/` 的含义

   指向**当前磁盘的根目录**。

2. 现象

   若 HTML 位于 `D:/projects/index.html`，代码中写 `/css/style.css`，浏览器会去 `D:/css/style.css` 寻找文件，而非项目目录下的 CSS，从而导致 404 错误。

### 使用 Live Server 启动

当使用 VS Code 的 Live Server 插件时，本地会启动一个微型 HTTP 服务器。

1. `/` 的含义

   指向**网站根目录**（即 VS Code 当前打开的工作区文件夹）。

2. 现象

   此时 `/css/style.css` 会被正确解析为“项目根目录下的 css 文件夹”，路径匹配成功。

## 代码示例

为了避免因环境差异导致的路径混乱，建议遵循以下规范：

1. 优先使用相对路径

   在 HTML 或模块化代码中，尽量使用 `./` 或 `../` 来引用同级或上级目录的资源。这种方式在任何环境下都具有最高的可移植性。

2. 后端托管时的路径分离

   在 FastAPI 等后端框架中，需严格区分“URL 路径”与“物理路径”。

     ```python
   from fastapi import FastAPI
   from fastapi.staticfiles import StaticFiles
   
   app = FastAPI()
   
   # URL 路径（网站根目录下的 /static）
   # 物理路径（相对于启动脚本的本地 static 文件夹）
   app.mount("/static", StaticFiles(directory="static"), name="static")
     ```

3. 动态构建绝对路径

    在编写后端脚本或自动化任务时，若必须使用绝对路径，应基于当前文件位置动态计算，而非硬编码盘符。

    ```python
    from pathlib import Path
    
    # 获取当前脚本所在目录，拼接 static 文件夹
    # 无论从哪里启动程序，都能准确定位
    static_dir = Path(__file__).parent / "static"
    ```

# 交互文档的配置

## 介绍

在使用 API 可视化交互式文档的过程中，有时候相关网络是正常的，但是依然无法正常加载可视化 API 文档界面，这是因为 swagger_ui 内置的 HTML 模板资源（swagger-ui.css 和 swagger-ui.js）是从第三方 CDN 服务商上加载的。第三方服务出现问题就会导致无法正常加载可视化 API 文档。

要避免这种情况，可以自定义并渲染 HTML 模板中的一些变量，让资源从本地进行加载。

## 资源位置

docs 模板内容渲染的 HTML 内容在 `../FastAPI/openapi/docs.py` 模块中，里面有 `get_swagger_ui_html` 方法文档，其中有 HTML 输出模板的内容。替换对应输出模板的参数实现本地资源的加载。

`get_swagger_ui_html` 是 FastAPI 框架中用于生成并返回 Swagger UI 交互式 API 文档 HTML 页面的核心工具函数；该函数通常在需要自定义文档 UI 的静态资源加载地址（例如将默认的国外 CDN 替换为国内镜像或本地自托管文件）、修改文档页面标题或配置 OAuth2 认证参数时使用，通过禁用默认的文档路由并手动创建自定义路由来调用此函数，从而实现对 API 文档页面的完全控制。

### 使用时的格式

```python
from fastapi.openapi.docs import get_swagger_ui_html

get_swagger_ui_html(
    *,  # 强制后续参数必须使用关键字传参
    openapi_url,  # Swagger UI 应该加载并使用的 OpenAPI JSON 规范地址（通常为 "/openapi.json"）
    title,  # 生成的 HTML 页面的标题，通常显示在浏览器标签页中
    swagger_js_url="https://cdn.jsdelivr.net/npm/swagger-ui-dist@5/swagger-ui-bundle.js",  # 用于加载 Swagger UI JavaScript 文件的 URL（默认为国外 CDN）
    swagger_css_url="https://cdn.jsdelivr.net/npm/swagger-ui-dist@5/swagger-ui.css",  # 用于加载 Swagger UI CSS 样式文件的 URL（默认为国外 CDN）
    swagger_favicon_url="https://fastapi.tiangolo.com/img/favicon.png",  # 浏览器标签页显示的 Favicon 图标 URL
    oauth2_redirect_url=None,  # OAuth2 认证的重定向 URL，通常由 FastAPI 自动处理，默认为 None
    init_oauth=None,  # 包含 Swagger UI OAuth2 初始化配置的字典，默认为 None
    swagger_ui_parameters=None  # 传递给 Swagger UI 的额外配置参数字典（如禁用语法高亮、设置主题等），默认为 None
)
```

### 参数详细说明

| 参数名                  | 作用说明                                            | 常见可选值或类型                                             |
| ----------------------- | --------------------------------------------------- | ------------------------------------------------------------ |
| `openapi_url`           | 指定 Swagger UI 获取 API 规范数据的地址             | 字符串，如 `"/openapi.json"`、`app.openapi_url`              |
| `title`                 | 设置文档页面的 HTML `<title>` 标签内容              | 字符串，如 `"API 文档"`、`app.title + " - Swagger UI"`       |
| `swagger_js_url`        | 指定 Swagger UI 核心 JavaScript 文件的加载地址      | 字符串，如国内 CDN 地址、本地静态文件路径 `"/static/swagger-ui-bundle.js"` |
| `swagger_css_url`       | 指定 Swagger UI 样式表 CSS 文件的加载地址           | 字符串，如国内 CDN 地址、本地静态文件路径 `"/static/swagger-ui.css"` |
| `swagger_favicon_url`   | 指定文档页面的网站图标地址                          | 字符串，如 `"https://fastapi.tiangolo.com/img/favicon.png"`  |
| `oauth2_redirect_url`   | 指定 OAuth2 认证流程的重定向端点                    | 字符串或 `None`，通常使用 `app.swagger_ui_oauth2_redirect_url` |
| `init_oauth`            | 传递 OAuth2 的初始化配置（如 client_id、scopes 等） | 字典或 `None`，如 `{"clientId": "my-client", "scopes": ["read", "write"]}` |
| `swagger_ui_parameters` | 传递 Swagger UI 的 UI 行为配置参数                  | 字典或 `None`，如 `{"syntaxHighlight": False, "deepLinking": True}` |

### 代码示例

以下示例展示了如何禁用默认的文档路由，并使用 `get_swagger_ui_html` 创建一个使用国内 CDN 加速的自定义 Swagger UI 文档页面：

```python
from fastapi import FastAPI
from fastapi.openapi.docs import get_swagger_ui_html

app = FastAPI(
    title="自定义文档示例",
    docs_url=None,  # 1. 禁用默认的 /docs 路由
    redoc_url=None  # 2. 可选：同时禁用默认的 /redoc 路由
)

# 3. 手动创建自定义的 /docs 路由
@app.get("/docs", include_in_schema=False)
async def custom_swagger_ui_html():
    return get_swagger_ui_html(
        openapi_url=app.openapi_url,  # 指向自动生成的 OpenAPI JSON 地址
        title=app.title + " - Swagger UI",  # 设置页面标题
        swagger_js_url="https://unpkg.com/swagger-ui-dist@5/swagger-ui-bundle.js",  # 替换为国内/自定义 JS CDN
        swagger_css_url="https://unpkg.com/swagger-ui-dist@5/swagger-ui.css",  # 替换为国内/自定义 CSS CDN
        swagger_ui_parameters={
            "syntaxHighlight": False,  # 禁用代码语法高亮
            "deepLinking": True       # 启用深度链接
        }
    )
```

## 更改步骤

1. 下载对应的 css 和 js 文件，放在 static 文件夹中。

2. 挂载静态资源文件，设置读取路径并自定义访问 docs 的路由。

   *不挂载也行，只要设置了 js 和 css 的路径就行了。*
