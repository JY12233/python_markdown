# 路由概述

路由是 FastAPI 框架中用于将 HTTP 请求映射到具体处理函数的核心机制。其本质是建立“URL 路径 + HTTP 方法”与“Python 异步/同步函数”之间的**绑定**关系。

当客户端发起请求时，FastAPI 会根据预定义的路由规则，将请求精准分发到对应的处理函数（即路径操作函数），并自动完成参数解析、数据验证及响应序列化。

## 核心作用

- 请求分发

  根据 URL 路径和 HTTP 方法（GET、POST、PUT、DELETE 等）将请求导向正确的业务逻辑。

- 参数自动提取

  自动从 URL 路径、查询字符串、请求头及请求体中提取参数，并传递给处理函数。

- 数据验证与转换

  基于 Python 类型提示（Type Hints）和 Pydantic 模型，自动验证输入数据的类型与格式，无效数据会触发 422 错误。

- 文档自动生成

  所有注册的路由会自动被扫描并生成符合 OpenAPI 规范的交互式文档（Swagger UI / ReDoc）。

- 依赖注入支持

  路由函数支持声明依赖项，框架会在执行处理函数前自动解析并注入所需的资源（如数据库会话、当前用户信息）。

## 基础使用方式

路由通常通过 `FastAPI` 应用实例或 `APIRouter` 实例提供的装饰器进行定义。

### 基础路由

使用 `@app.get()`、`@app.post()` 等装饰器绑定路径与处理函数。

```python
from fastapi import FastAPI

app = FastAPI()

# 定义一个处理 GET 请求的路由
@app.get("/items/")
async def read_items():
    return [{"name": "Item1"}, {"name": "Item2"}]
```

### 路径参数

Path Parameters。在路径中使用花括号 `{}` 定义动态参数，**参数名需与函数形参一致**。

```python
# 访问 /items/42 时，item_id 自动解析为整数 42
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}
```

### 查询参数

Query Parameters。函数中未出现在路径中的参数，默认被视为查询参数。

```python
# 访问 /items/?skip=0&limit=10
@app.get("/items/")
async def read_items(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}
```

### 请求体

Request Body。使用 Pydantic 模型定义请求体结构，FastAPI 会自动解析 JSON 并验证。

```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    price: float

@app.post("/items/")
async def create_item(item: Item):
    return item
```

## 模块化路由

APIRouter。当项目规模扩大时，为避免单文件代码臃肿，可使用 `APIRouter` 将路由按业务模块拆分。

*在 01 篇中有介绍。*

### 创建路由模块

在独立文件（如 `routers/users.py`）中定义路由组。

```python
from fastapi import APIRouter

router = APIRouter(
    prefix="/users",      # 为该组路由添加统一前缀
    tags=["用户管理"]     # 在文档中进行分组
)

@router.get("/")
async def get_users():
    return ["Alice", "Bob"]

@router.get("/{user_id}")
async def get_user(user_id: int):
    return {"user_id": user_id}
```

### 挂载路由到主应用

在主入口文件中使用 `include_router` 方法注册路由模块。

```python
from fastapi import FastAPI
from routers import users

app = FastAPI()

# 将 users 模块的路由挂载到主应用
app.include_router(users.router)
```

## 路由执行流程

1. 请求到达

   客户端发送 HTTP 请求至服务器。

2. 路由匹配

   FastAPI 遍历已注册的路由列表，寻找路径与 HTTP 方法均匹配的处理器。

3. 参数解析

   框架从 URL、查询字符串、请求头或请求体中提取参数，并根据类型提示进行验证与转换。

4. 依赖解析

   执行路由函数声明的所有依赖项（如数据库连接、鉴权检查）。

5. 执行处理函数

   调用匹配的路径操作函数，传入解析后的参数。

6. 响应序列化

   将函数返回值转换为 JSON（或其他指定格式），并设置正确的状态码与响应头返回给客户端。

# 路由节点元数据

路由节点元数据（Path Operation Metadata）是附加在单个路由（路径操作）上的描述性信息。这些信息不会改变路由的实际业务逻辑，但会被 FastAPI 自动提取并写入 OpenAPI 规范（Schema），最终用于生成自动化的交互式 API 文档（如 Swagger UI 和 ReDoc）。

路由节点元数据是一组用于描述数据的数据，主要用于组织、查找和理解数据（通常指描述数据属性的信息）。

元数据的核心价值在于实现“代码即文档”，确保接口文档与代码实现始终保持同步。

## 核心作用

- 文档自动生成

  为自动生成的 API 文档提供标题、详细描述、分组标签等展示信息，提升文档的可读性与专业性。

- 接口状态管理

  通过标记废弃（Deprecated）或隐藏（Include in Schema）来管理接口的生命周期，引导调用方使用新接口。

- 响应模型控制

  定义接口的响应数据结构、状态码及字段过滤规则，确保返回数据的规范性与安全性。

- 唯一标识与扩展

  自定义操作 ID 以便于客户端代码生成，或通过 `openapi_extra` 扩展非标准的 OpenAPI 字段。

## 常用元数据参数详解

以下参数通常在路由装饰器（如 `@app.get()`）或 `APIRouter` 中声明。

| 参数名                            | 作用说明                                   | 常见可选值或类型                               |
| --------------------------------- | ------------------------------------------ | ---------------------------------------------- |
| `path`                            | 定义路由的 URL 路径模板                    | 字符串，如 `"/users/{user_id}"`                |
| `response_model`                  | 声明响应数据的结构和类型                   | Pydantic 模型类、`None`                        |
| `status_code`                     | 设置默认的成功响应状态码                   | 整数，如 `200`、`201`、`204`                   |
| `tags`                            | 在自动文档中对接口进行分组                 | 字符串列表，如 `["用户模块"]`                  |
| `dependencies`                    | 声明该路由的前置依赖项                     | 依赖项列表，如 `[Depends(auth)]`               |
| `summary`                         | 接口在文档列表中的简短标题                 | 字符串                                         |
| `description`                     | 接口的详细说明，支持 Markdown              | 字符串                                         |
| `response_description`            | 对成功响应内容的文字说明                   | 字符串，默认为 `"Successful Response"`         |
| `responses`                       | 定义额外的响应状态码及描述                 | 字典，如 `{404: {"description": "Not found"}}` |
| `deprecated`                      | 标记接口为已弃用状态                       | `True`，`False`（默认）                        |
| `operation_id`                    | 自定义 OpenAPI 操作 ID                     | 字符串，需全局唯一                             |
| `response_model_include`          | 指定响应模型中需保留的字段                 | 集合或列表                                     |
| `response_model_exclude`          | 指定响应模型中需过滤的字段                 | 集合或列表                                     |
| `response_model_by_alias`         | 是否启用响应模型的字段别名                 | `True`（默认），`False`                        |
| `response_model_exclude_unset`    | 是否排除未显式赋值的字段                   | `True`，`False`（默认）                        |
| `response_model_exclude_defaults` | 是否排除等于默认值的字段                   | `True`，`False`（默认）                        |
| `response_model_exclude_none`     | 是否排除值为 `None` 的字段                 | `True`，`False`（默认）                        |
| `include_in_schema`               | 控制接口是否展示在文档中                   | `True`（默认），`False`                        |
| `response_class`                  | 指定默认的响应类 <br />`Response`          | `JSONResponse`（默认）、`HTMLResponse` 等      |
| `name`                            | 路由的内部名称。<br />优先显示 `summary`。 | 字符串，默认为函数名                           |
| `callbacks`                       | 定义 OpenAPI 回调路由                      | 路由列表                                       |
| `openapi_extra`                   | 添加自定义 OpenAPI 扩展字段                | 字典                                           |
| `generate_unique_id_function`     | 自定义生成路由唯一 ID 的逻辑               | 可调用对象                                     |

## 形参代码示例

```python
@app.get(
    path,  # 路由的 URL 路径，支持路径参数（如 "/items/{item_id}"）
    *,  # 强制后续参数必须使用关键字传参
    response_model=None,  # 响应数据的 Pydantic 模型，用于验证和文档生成
    status_code=200,  # 默认的成功响应状态码
    tags=None,  # OpenAPI 文档中的分组标签列表
    dependencies=None,  # 该路由专属的依赖项列表
    summary=None,  # OpenAPI 文档中的接口简短摘要
    description=None,  # OpenAPI 文档中的接口详细描述，支持 Markdown
    response_description="Successful Response",  # 成功响应的描述文本
    responses=None,  # 额外的响应状态码及描述字典
    deprecated=None,  # 是否标记该接口为已弃用
    operation_id=None,  # 自定义 OpenAPI 操作 ID，需保证全局唯一
    response_model_include=None,  # 响应模型中需要包含的字段集合
    response_model_exclude=None,  # 响应模型中需要排除的字段集合
    response_model_by_alias=True,  # 是否使用响应模型中的字段别名
    response_model_exclude_unset=False,  # 是否排除未显式设置的字段
    response_model_exclude_defaults=False,  # 是否排除具有默认值的字段
    response_model_exclude_none=False,  # 是否排除值为 None 的字段
    include_in_schema=True,  # 是否将该路由包含在 OpenAPI 文档中
    response_class=Default(JSONResponse),  # 默认的响应类
    name=None,  # 路由的内部名称，用于生成唯一 ID 和反向链接
    callbacks=None,  # OpenAPI 回调定义列表
    openapi_extra=None,  # 额外的 OpenAPI 扩展元数据字典
    generate_unique_id_function=Default(generate_unique_id),  # 生成唯一 ID 的自定义函数
)
```

## 使用方式与代码示例

元数据直接作为参数传入路由装饰器中。以下示例展示了如何为一个获取商品信息的接口配置完整的元数据：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ItemResponse(BaseModel):
    id: int
    name: str
    price: float
    secret_info: str  # 敏感字段，需在响应中排除

@app.get(
    "/items/{item_id}",
    summary="获取商品信息",  # 接口简短摘要
    description="根据商品 ID 获取商品的详细信息。\n\n支持返回商品名称和价格。",  # 详细描述，支持 Markdown
    response_description="商品信息对象",  # 响应描述
    tags=["商品管理"],  # 分组标签
    response_model=ItemResponse,  # 响应模型
    response_model_exclude={"secret_info"},  # 排除敏感字段
    responses={  # 额外响应定义
        404: {"description": "商品未找到"},
        500: {"description": "服务器内部错误"}
    },
    deprecated=False,  # 是否废弃
    include_in_schema=True,  # 是否在文档中显示
)
async def read_item(item_id: int):
    return {
        "id": item_id, 
        "name": "示例商品", 
        "price": 99.9, 
        "secret_info": "内部成本价"
    }
```

> **补充说明：Docstring 与 Description 的关系**
>
> 若在路由装饰器中未设置 `description` 参数，FastAPI 会自动提取该路由函数的文档字符串（Docstring）作为接口的详细描述。若同时设置了 `description` 参数和 Docstring，则 `description` 参数的优先级更高。此外，在 Docstring 中使用 `\f`（换页符）可以截断文档字符串，`\f` 之后的内容不会出现在 OpenAPI 文档中，但可被 Sphinx 等其他文档工具读取。

# `class` / `model` 的区别

在 FastAPI 中，`response_class` 和 `response_model` 虽然都用于控制响应，但它们的作用层面完全不同。简而言之，`response_class` 决定的是**“用什么格式发送数据”**，而 `response_model` 决定的是**“发送的数据长什么样”**。

## 区别

| 对比维度     | `response_class`                                    | `response_model`                           |
| ------------ | --------------------------------------------------- | ------------------------------------------ |
| **控制层面** | HTTP 响应类型（媒体类型）                           | JSON 数据结构（字段与类型）                |
| **核心作用** | 告诉客户端如何解析响应（如 HTML、文件、纯文本）     | 定义接口暴露哪些字段，并自动过滤、验证数据 |
| **常见取值** | `HTMLResponse`、`FileResponse`、`PlainTextResponse` | Pydantic 模型类（如 `UserResponse`）       |
| **数据过滤** | 不进行任何字段过滤                                  | 自动过滤掉模型中未定义的字段（保障安全性） |
| **文档生成** | 影响文档中的 `Content-Type` 媒体类型                | 生成详细的 JSON Schema 数据结构文档        |

## 详细解析

### `response_class`

它指定了 FastAPI 使用哪种响应类来封装返回的数据。这直接决定了 HTTP 响应头中的 `Content-Type`。

- 适用场景

  当接口返回的不是标准的 JSON 数据时。例如返回一个 HTML 网页、一个文件下载、一段纯文本或一个重定向。

- 行为

  如果设置了 `response_class=HTMLResponse`，FastAPI 会将返回的字符串直接作为 HTML 内容发送，而不会将其序列化为 JSON 字符串。

### `response_model`

它接收一个 Pydantic 模型，用于对返回的数据进行序列化、验证和过滤。

- 适用场景

  当接口返回 JSON 数据，但需要隐藏敏感字段（如密码）、统一数据格式或确保数据类型正确时。

- 行为

  即使函数返回了一个包含 10 个字段的字典，如果 `response_model` 只定义了 3 个字段，FastAPI 会自动过滤掉多余的 7 个字段，只返回这 3 个字段。

## 组合使用

在大多数标准的 JSON API 开发中，通常只需要使用 `response_model`，因为默认的 `response_class` 就是 `JSONResponse`。

但在某些特殊场景下，两者可以组合使用：

- 自定义 JSON 响应类

  如果希望使用更高性能的 JSON 序列化库（如 `orjson`），可以自定义一个 `CustomORJSONResponse`，然后通过 `response_class=CustomORJSONResponse` 指定响应类，同时依然使用 `response_model` 来保证数据结构的正确性。

- 文档与实现分离

  可以在装饰器中声明 `response_class` 以在 OpenAPI 文档中正确记录媒体类型，同时在函数内部直接返回一个 `Response` 对象以完全控制响应内容。

## 代码示例

```python
from fastapi import FastAPI
from fastapi.responses import HTMLResponse, JSONResponse
from pydantic import BaseModel

app = FastAPI()

# 1. 使用 response_model：控制 JSON 数据的字段
class UserResponse(BaseModel):
    username: str
    email: str

@app.get("/user", response_model=UserResponse)
async def get_user():
    # 即使返回了 password，response_model 也会将其自动过滤
    return {
        "username": "alice", 
        "email": "alice@example.com", 
        "password": "secret123"
    }

# 2. 使用 response_class：控制响应为 HTML 格式
@app.get("/home", response_class=HTMLResponse)
async def get_home():
    # 直接返回 HTML 字符串，不会被包裹在 JSON 引号中
    return "<h1>欢迎来到首页</h1>"
```

# 多重 URL 绑定

多重 URL 绑定（Multiple URL Binding）是指在 FastAPI 中，将**多个不同**的 URL 路径或 HTTP 请求方法绑定到**同一个**视图函数（路径操作函数）上的技术。通过这种机制，同一个函数可以响应多个不同的请求入口，从而避免编写重复的逻辑代码。

## 实现方式

多重 URL 绑定主要通过**叠加多个路由装饰器**来实现。FastAPI 允许在同一个函数定义上方连续使用多个 `@app.get()`、`@app.post()` 等装饰器。

## 代码示例

以下示例展示了如何将 `/`、`/index` 以及 `POST /index` 这三个不同的请求入口绑定到同一个 `app_hello` 函数上.

```python
from fastapi import FastAPI
from starlette.responses import JSONResponse

app = FastAPI()

# 叠加多个装饰器，实现多重 URL 绑定
@app.get('/', response_class=JSONResponse)
@app.get('/index', response_class=JSONResponse)
@app.post('/index', response_class=JSONResponse)
async def app_hello():
    return {"Hello": "app api"}
```

## 请求匹配结果

- 发送 `GET /` 请求 -> 返回 `{"Hello": "app api"}`
- 发送 `GET /index` 请求 -> 返回 `{"Hello": "app api"}`
- 发送 `POST /index` 请求 -> 返回 `{"Hello": "app api"}`

## 核心应用场景

- 兼容旧版 API 路径

  当接口路径发生重构时（例如从 `/index` 变更为 `/`），可以通过多重绑定让新旧路径同时生效，确保旧客户端不会报错。

- 同一逻辑支持多种请求方式

  某些接口既需要支持 `GET` 请求查看状态，又需要支持 `POST` 请求触发操作，且两者的处理逻辑完全一致。

- 减少代码冗余

  避免为相同的业务逻辑复制粘贴多份完全相同的函数代码，提升代码的可维护性。

## 注意事项

- `response_class` 可省略

  示例中的 `response_class=JSONResponse` 其实是 FastAPI 的默认行为，可以省略不写。但显式写出有助于提升代码的可读性。

- 函数命名规范

  虽然多个装饰器指向同一个函数，但该函数仍需保持唯一的命名，不能出现 Python 函数名冲突的情况。

# 路由的分类

在 FastAPI 中，路由根据路径的固定性分为**静态路由与动态路由**。

- 静态路由是指路径完全固定、不包含任何变量的 URL。

- 动态路由则是指在路径中包含由花括号 `{}` 包裹的变量（即路径参数）的 URL。

两者共同构成了 Web 框架的请求分发机制，用于精准定位资源并提取请求中的关键标识信息。

## 静态路由

### 定义与作用

静态路由的路径是写死的，不包含任何动态变量。其主要作用是处理固定资源的请求，例如获取首页内容、获取固定的配置信息或执行特定的操作。

### 使用方式

直接在路由装饰器中定义固定的路径字符串。

```python
from fastapi import FastAPI

app = FastAPI()

# 静态路由：路径固定为 /about
@app.get("/about")
async def get_about():
    return {"message": "这是关于页面"}
```

## 动态路由

### 定义与作用

动态路由允许在路径中定义变量（路径参数）。当客户端请求该路径时，FastAPI 会自动提取 URL 中对应位置的值，并将其作为函数参数传递给处理函数。其核心作用是用于定位特定的资源，例如根据用户 ID 获取用户详情、根据商品 ID 删除商品等。

### 使用方式

在路径中使用 `{变量名}` 声明动态参数，并在处理函数的形参中定义同名参数。FastAPI 会根据类型提示自动进行数据转换与校验。

```python
# 动态路由：{item_id} 是路径参数
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}
```

## 核心差异对比

| 对比维度     | 静态路由           | 动态路由                           |
| ------------ | ------------------ | ---------------------------------- |
| **路径特征** | 完全固定，无变量   | 包含 `{变量名}` 占位符             |
| **核心作用** | 处理固定资源或操作 | 根据标识符定位特定资源             |
| **参数传递** | 无路径参数         | 自动提取 URL 中的值并传入函数      |
| **类型校验** | 不涉及             | 基于类型提示自动校验并转换数据类型 |

## 路由匹配优先级

当多个路由可能匹配同一个 URL 时，FastAPI 严格按照代码中的**定义顺序从上到下**依次匹配。因此，固定路径的静态路由必须定义在动态路由之前，否则动态参数会将固定路径的值“吞掉”。

```python
# 正确顺序：静态路由在前，动态路由在后
@app.get("/users/me")
async def read_user_me():
    return {"user_id": "当前登录用户"}

@app.get("/users/{user_id}")
async def read_user(user_id: int):
    return {"user_id": user_id}
```

## 路径参数的类型与校验

动态路由支持多种标准 Python 类型，FastAPI 会自动进行类型转换与数据校验。若传入的值无法转换为声明的类型，将自动返回 422 错误响应。

| 类型        | 说明               | URL 示例              |
| ----------- | ------------------ | --------------------- |
| `str`       | 字符串（默认类型） | `/items/foo`          |
| `int`       | 整数               | `/items/5`            |
| `float`     | 浮点数             | `/items/5.5`          |
| `bool`      | 布尔值             | `/items/true`         |
| `uuid.UUID` | UUID 字符串        | `/items/3fa85f64-...` |

## 预设值的路径参数（Enum）

当需要限制路径参数只能是几个固定值时，可使用 Python 的 `Enum` 类型。这结合了静态路由的确定性与动态路由的灵活性。

```python
from enum import Enum
from fastapi import FastAPI

class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"

app = FastAPI()

@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):
    return {"model_name": model_name, "message": "模型选择成功"}
```

# APIRouter 介绍

`APIRouter` 是 FastAPI 框架中用于实现模块化路由管理的核心类，本质上是一个轻量级的“迷你应用”；在开发中，通过实例化该类将不同业务模块（如用户管理、订单系统）的路由拆分到独立文件中，最后在主应用中使用 `include_router()` 方法进行统一挂载，通常在项目规模扩大、需要按功能域解耦代码或实现 API 版本控制时使用。

> 我的理解，`APIRouter` 就像 matplotlib 中的子图，`app` 就相当于直接使用 `plt`

## 创建对象时的格式

```python
from fastapi import APIRouter

router = APIRouter(
    prefix="",  # 为当前路由组下的所有路径添加统一的 URL 前缀
    tags=None,  # 为当前路由组下的所有路径操作添加 OpenAPI 文档标签列表
    dependencies=None,  # 为当前路由组下的所有路径操作添加全局依赖项列表
    default_response_class=Default(JSONResponse),  # 设置当前路由组默认的响应类
    responses=None,  # 为当前路由组下的所有路径操作添加额外的响应定义
    callbacks=None,  # 为当前路由组下的所有路径操作添加 OpenAPI 回调定义
    routes=None,  # 传入预定义的路由列表（继承自 Starlette，通常不建议使用）
    redirect_slashes=True,  # 是否自动重定向带或不带尾部斜杠的路径
    default=None,  # 默认的路由处理函数，用于处理 404 等未匹配请求
    dependency_overrides_provider=None,  # 依赖项覆盖的提供者，默认指向主应用对象
    route_class=APIRoute,  # 自定义的路由类，用于扩展或修改路由行为
    on_startup=None,  # 路由组启动时执行的回调函数列表（已弃用，建议使用 lifespan）
    on_shutdown=None,  # 路由组关闭时执行的回调函数列表（已弃用，建议使用 lifespan）
    deprecated=None,  # 是否将当前路由组下的所有路径操作标记为已弃用
    include_in_schema=True,  # 是否将当前路由组下的所有路径操作包含在 OpenAPI 文档中
    generate_unique_id_function=Default(generate_unique_id),  # 自定义生成路由唯一 ID 的函数
)
```

## 参数详细说明

| 参数名                          | 作用说明                             | 常见可选值或类型                                             |
| ------------------------------- | ------------------------------------ | ------------------------------------------------------------ |
| `prefix`                        | 设置路由组的统一路径前缀             | 字符串，如 `"/users"`、`"/v1/items"`，默认为 `""`            |
| `tags`                          | 设置路由组在文档中的分组标签         | 字符串列表或枚举列表，如 `["用户管理"]`，默认为 `None`       |
| `dependencies`                  | 设置路由组的全局依赖项               | 依赖项列表，如 `[Depends(verify_token)]`，默认为 `None`      |
| `default_response_class`        | 设置路由组的默认响应类               | 响应类，如 `JSONResponse`、`HTMLResponse`，默认为 `JSONResponse` |
| `responses`                     | 设置路由组额外的响应状态码及描述     | 字典，如 `{404: {"description": "Not found"}}`，默认为 `None` |
| `callbacks`                     | 设置路由组的 OpenAPI 回调定义        | 路由列表，默认为 `None`                                      |
| `routes`                        | 传入预定义的路由对象列表             | 路由列表，默认为 `None`（继承自 Starlette，不推荐使用）      |
| `redirect_slashes`              | 控制是否自动处理路径末尾斜杠的重定向 | `True`（默认），`False`                                      |
| `default`                       | 设置路由组的默认处理函数             | ASGI 应用或可调用对象，默认为 `None`                         |
| `dependency_overrides_provider` | 指定依赖项覆盖的提供者对象           | 任意对象，默认为 `None`（通常由主应用自动处理）              |
| `route_class`                   | 自定义路由类以扩展路由行为           | `APIRoute` 的子类，默认为 `APIRoute`                         |
| `on_startup`                    | 路由组启动时执行的回调函数列表       | 函数列表，默认为 `None`（已弃用）                            |
| `on_shutdown`                   | 路由组关闭时执行的回调函数列表       | 函数列表，默认为 `None`（已弃用）                            |
| `deprecated`                    | 标记路由组下所有接口为已弃用状态     | `True`，`False`（默认）                                      |
| `include_in_schema`             | 控制路由组是否展示在 OpenAPI 文档中  | `True`（默认），`False`                                      |
| `generate_unique_id_function`   | 自定义生成路由唯一 ID 的逻辑         | 可调用对象，默认为 `generate_unique_id`                      |

## 代码示例

以下是一个使用 `APIRouter` 进行模块化路由拆分的完整代码示例。该示例展示了如何将“用户管理”相关的路由从主应用中剥离，并在主应用中进行统一挂载。

> 写在一个模块中也是可以的。

### 创建路由模块

在独立文件中定义业务路由，使用 `APIRouter` 替代 `FastAPI` 实例。

```python
from fastapi import APIRouter

# 1. 实例化路由，并配置统一前缀和文档标签
router = APIRouter(
    prefix="/users",       # 为该模块下的所有路由添加 /users 前缀
    tags=["用户管理"]      # 在自动生成的文档中归入“用户管理”分组
)

# 2. 定义获取所有用户的路由（最终路径为 /users/）
@router.get("/")
async def get_users():
    return [
        {"id": 1, "name": "张三"},
        {"id": 2, "name": "李四"}
    ]

# 3. 定义获取单个用户的路由（最终路径为 /users/{user_id}）
@router.get("/{user_id}")
async def get_user(user_id: int):
    return {"id": user_id, "name": f"用户{user_id}"}
```

### 主应用入口

在主应用中导入路由模块，并使用 `include_router` 方法进行挂载。

```python
from fastapi import FastAPI
from routers import users  # 导入刚才创建的路由模块

app = FastAPI(title="APIRouter 示例项目")

# 将 users 模块的路由挂载到主应用
app.include_router(users.router)

# 主应用也可以定义自己的根路由
@app.get("/")
async def root():
    return {"message": "欢迎来到 APIRouter 示例项目"}
```

### 运行效果说明

启动主应用后，访问自动生成的交互式文档（`/docs`），可以看到：

- 接口被清晰地归类在“用户管理”标签下。
- 所有用户相关接口的路径都自动带上了 `/users` 前缀。
- 主应用的根路由 `/` 依然正常工作。

这种拆分方式能有效避免主文件代码臃肿，使项目结构更加清晰、易于维护。

## 与 APIRoute 的区别

`APIRoute` 与 `APIRouter` 在 FastAPI 中扮演着完全不同的角色。简单来说，`APIRouter` 是一个用于组织和管理路由的“容器”，而 `APIRoute` 则是代表单个具体接口的“节点对象”。

### 核心区别对比

| 对比维度     | APIRouter                                          | APIRoute                                         |
| ------------ | -------------------------------------------------- | ------------------------------------------------ |
| **本质定位** | 路由容器（类似于 Flask 的蓝图）                    | 具体的路由节点对象                               |
| **核心作用** | 将相关的路由分组管理，实现模块化                   | 定义单个具体的 HTTP 接口（路径、方法、处理函数） |
| **使用方式** | 实例化后，通过装饰器注册多个路由，最后挂载到主应用 | 通常由框架在后台自动创建，极少需要手动实例化     |
| **包含关系** | 一个 `APIRouter` 内部包含多个 `APIRoute`           | 一个 `APIRoute` 属于某个 `APIRouter` 或主应用    |

### 详细解析

#### APIRouter

`APIRouter` 的主要目的是解决代码结构问题。当项目变大时，将所有接口写在 `main.py` 中会导致文件臃肿。`APIRouter` 允许将不同业务模块（如用户管理、商品管理）的路由拆分到独立文件中，最后再统一挂载到主应用上。

`APIRouter` 就像一个“路由收纳盒”，可以把不同功能的接口放进不同的盒子里，最后再把所有盒子统一放到“大柜子”（主应用 `app`）里。

#### APIRoute

`APIRoute` 代表了一个具体的 HTTP 端点。它包含了该接口的所有元数据，例如 URL 路径、允许的 HTTP 方法（GET/POST 等）、处理函数、响应模型等。

在日常开发中，当使用 `@router.get("/items")` 装饰器时，FastAPI 会在后台自动创建一个 `APIRoute` 对象并将其添加到 `APIRouter` 的路由列表中。开发者通常不需要手动去 `new` 一个 `APIRoute` 对象。

### 代码示例对比

以下代码直观展示了两者在代码层面的区别。

```python
from fastapi import FastAPI, APIRouter
from fastapi.routing import APIRoute

# 1. APIRouter：创建一个路由容器
user_router = APIRouter(prefix="/users", tags=["用户管理"])

# 2. APIRoute：通过装饰器隐式创建具体的路由节点
# 框架会在后台自动生成 APIRoute 对象并注册到 user_router 中
@user_router.get("/{user_id}")
async def get_user(user_id: int):
    return {"user_id": user_id}

# 3. 将包含多个 APIRoute 的 APIRouter 挂载到主应用
app = FastAPI()
app.include_router(user_router)
```

总结而言，`APIRouter` 关注的是**“如何组织和分组”**，而 `APIRoute` 关注的是**“单个接口的具体定义”**。在绝大多数开发场景中，开发者主要与 `APIRouter` 打交道，而 `APIRoute` 则作为底层概念由框架自动管理。
