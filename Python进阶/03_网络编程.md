# 网络编程

## 概念

1.  网络

   > 将具有独立功能的**多台计算机**通过通信线路和通信设备连接起来，在网络管理软件及网络通信协议下，实现资源共享和信息传递的虚拟平台。

2.  网络编程

   > 编写基于网络通信的软件或程序。网络编程也叫网络通信，Socket通信，即：通信双方都独有自己的Socket对象，数据在Socket之间通过 数据报文(UDP协议) 或者 字节流(TCP协议) 的形式进行传输.

## 三要素

1. IP地址

   - 概念

     > 网络环境下每台计算机的唯一标识，通过IP地址来找到指定的计算机。

   - 分类

     - IPv4

       > 采用4字节，十进制，每个单位上限到255（1个byte：-128 ~ 127）。

       比如：192.168.199.161。

       总共有256 ^ 4个（0 ~ 255）。

     - IPv6

       > 8字节，16进制。

   - 检查IP

     > - `ipconfig` 
     > - `ipconfig/all` 

     物理地址（Physical Address）：计算机的唯一标识，通过这个可以锁定电脑。

     DHCP：动态分配IP。

   - 检查网络是否正常使用 ping 命令

     - `ping www.baidu.com`

       检查是否能上公网。可以加`  -t（windows）或者 -c（Linux）`表示循环，使用ctrl + c停止，不加只发送4次。

       ```cmd
       Pinging www.a.shifen.com [180.101.49.44] with 32 bytes of data:
       Reply from 180.101.49.44: bytes=32 time=9ms TTL=51
       Reply from 180.101.49.44: bytes=32 time=11ms TTL=51
       Reply from 180.101.49.44: bytes=32 time=11ms TTL=51
       Reply from 180.101.49.44: bytes=32 time=9ms TTL=51
       
       Ping statistics for 180.101.49.44:
           Packets: Sent = 4, Received = 4, Lost = 0 (0% loss),
       Approximate round trip times in milli-seconds:
           Minimum = 9ms, Maximum = 11ms, Average = 10ms
       ```

       `time`：延迟。

       `Sent`：发送数量。

       `Received`：接受数量。

       `Lost`：丢包数量。

     - `ping 当前局域网的ip地址` 检查是否在同一个局域网内

     - `ping 127.0.0.1` 检查本地网卡是否正常

2. 端口

   > 用于标识进程的逻辑地址，通过端口来找到指定的进程。也是传输数据的通道，每个软件都有自己的端口。

3. 端口号（属于端口的内容，这里单独提出）

   - 概念

     > 即端口的id，如果两个软件的端口号一样，则它们不能共存。

   - 分类

     - 知名端口号

       >是指众所周知的端口号，范围从0到1023。

     - 动态端口号

       > 一般程序员开发应用程序使用的端口号称为动态端口号，范围是从1024到65535。

4. 协议

   > 定义通信规则，符合协议则可以通信，否则无法正常通信。
   
   | 特性     | TCP (传输控制协议)       | UDP (用户数据报协议)        |
   | -------- | ------------------------ | --------------------------- |
   | 连接方式 | 面向连接 (打电话)        | 无连接 (发广播)             |
   | 可靠性   | 高 (数据不丢失、不重复)  | 低 (不保证送达)             |
   | 传输方式 | 字节流 (Stream)          | 数据报 (Datagram)           |
   | 速度     | 较慢 (因为要确认、重传)  | 极快 (直接发)               |
   | 有序性   | 有序 (按顺序到达)        | 无序 (可能先发后到)         |
   | 资源消耗 | 高 (需要维护连接状态)    | 低 (轻量级)                 |
   | 适用场景 | 文件传输、网页浏览、邮件 | 视频直播、在线游戏、DNS查询 |
   | 双方     | 区分客户端和服务端       | 只有发出方和接收方          |
   
   | 特性      | 字节流 (Stream)                | 数据报 (Datagram)               |
   | --------- | ------------------------------ | ------------------------------- |
   | 比喻      | 水管里的水                     | 一辆辆快递车                    |
   | 数据边界  | 无边界 (数据粘连在一起)        | 有边界 (每条数据独立完整)       |
   | 发送/接收 | 发送 N 次，可能接收 M 次 (N≠M) | 发送 N 次，接收 N 次 (一一对应) |
   | 顺序      | 严格有序                       | 可能乱序                        |
   | 完整性    | 保证字节不丢失                 | 不保证送达，但送达的包内容完整  |
   | 对应协议  | TCP (`SOCK_STREAM`)            | UDP (`SOCK_DGRAM`)              |

## TCP协议

### 概念

> 通过IP地址能够找到对应的设备，然后再通过端口号找到对应的端口，再通过端口把数据传输给应用程序。要注意，数据不能随便发送，在发送之前还需要规则，以保证程序之间按照指定的规则来进行数据的通信，而这个规则就是TCP协议。

### TCP的概念

> TCP的英文全拼(Transmission Control Protocol)，简称传输控制协议，它是一种面向连接的、可靠的、基于字节流的传输层通信协议。

### 通信流程

创建连接 :arrow_right: 传输数据 :arrow_right:  关闭连接

TCP协议创建连接：3次握手



>三次握手（Three-Way Handshake）就是指建立一个TCP连接时，需要客户端和服务端总共发送3个包以确认连接的建立。
>
>- 第一次握手：客户端向服务端发送请求，等待服务端确认。
>- 第二次握手：服务端收到请求后知道客户端请求建立连接，回复给客户端以确认连接请求。
>- 第三次握手：客户端收到确认后，再次发送请求确认服务端，服务端收到正确请求后，如果正确则连接建立成功，完成三次握手，随后客户端与服务端之间可以开始传输数据了。

TCP协议断开连接：4次挥手

>四次挥手说TCP断开链接的时候需要经过4次确认。TCP连接是双向，A连接B、B连接A都要断开
>
>- 第一次挥手：当主机A（可以是客户端也可以是服务端）完成数据传输后，提出停止TCP连接的请求
>- 第二次挥手：主机B收到请求后对其作出响应，确认这一方向上的TCP连接将关闭
>- 第三次挥手：主机B端再提出反方向的连接关闭请求
>- 第四次挥手：主机A对主机B的请求进行确认，双方向的关闭结束

###  特点

- 面向连接
  - 通信双方必须先建立好连接才能进行数据传输，数据传输完成后，需要断开连接，以释放系统资源。

- 可靠传输

  - 都建立了连接，传输数据可靠

  - 必须要先建立连接，相对效率较低

  - 大多数服务器程序都是使用TCP协议开发的，比如文件下载，网页浏览等

  | `send`    | 发送数据。                   |
  | `close`   | 关闭和服务端端交互的socket。 |

1. 创建服务端套接字对象
2. 绑定端口号
3. 设置监听
4. 等待接受客户端的连接请求

## Socket套接字

### 介绍

socket -- n. 插座

进程之间进行通信的工具，进程之间的网络工具都需要基于Socket。它是一个**通信端点 （Endpoint）**，是应用程序与底层复杂的网络协议（如 TCP/IP）之间的一个**标准接口**。

### 创建

```python
# 导入socket
import socket

"""
创建socket对象
参数：
    AddressFamily : 地址族（IPv4或者IPv6），默认为socket.AF_INET（ipv4）或者socket.AF_INET6（ipv6）
    Type : Socket Type，Socket类型，TCP 还是 UDP，默认值：SOCK_STREAM（TCP） SOCK_DGRAM（UDP）
"""
socket_obj = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
print(socket_obj) # <socket.socket fd=300, family=2, type=1, proto=0>
```

- **`socket.socket`**: 这部分表明了对象的类型，即它是一个 `socket` 模块中的 `socket` 类实例。
- **`fd=300`**: 这是最重要的部分。
  - `fd` 是 **File Descriptor （文件描述符）** 的缩写。在 Unix/Linux 和 Windows 等操作系统中，一切皆文件，包括网络连接、磁盘文件、管道等，都被操作系统赋予一个唯一的整数 ID 来标识。
  - `fd=300` 表示操作系统为这个 Socket 分配的文件描述符是 `300`。Python 的 `socket` 对象内部就是通过这个 `fd` 来与操作系统内核进行交互，实现网络读写的。这个数字在每次运行程序时都可能不同。
- **`family=2`**: 这表示 Socket 使用的**地址族 （Address Family）**。
  - `2` 是常量 `socket.AF_INET` 的整数值，代表 **IPv4** 地址族。如果你创建的是一个使用 IPv6 的 Socket，这里可能会显示 `family=10` （`AF_INET6`）。
- **`type=1`**: 这表示 Socket 的**类型 （Type）**。
  - `1` 是常量 `socket.SOCK_STREAM` 的整数值，代表这是一个**流式套接字**，即使用 **TCP** 协议。TCP 提供可靠的、面向连接的字节流服务。
  - 如果是 UDP 套接字，这里会是 `type=2` （`SOCK_DGRAM`）。
- **`proto=0`**: 这表示 Socket 使用的**协议 （Protocol）**编号。
  - `0` 通常表示该协议由 `type` 参数自动选择。对于 `type=SOCK_STREAM` （TCP），`proto=0` 就意味着使用 TCP 协议本身。对于 `type=SOCK_DGRAM` （UDP），`proto=0` 意味着使用 UDP 协议。在绝大多数情况下，这个值都是 `0`。

### 创建服务端

```python
import socket

"""
服务器端开发：
    1. 创建服务器端的套接字对象
    2. 绑定IP与端口号
    3. 设置最大监听数
    4. 等待客户端相应
    5. 给客户端发送消息
    6. 接收客户端的信息并打印
    7. 释放资源
"""
# 创建服务器端的套接字对象（IPv4，TCP）
server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 绑定IP与端口号
server.bind(('127.0.0.1', 10086))

# 设置最大监听数
server.listen(5)

# 等待连接
client_socket, address = server.accept()

# 发送消息，需要把字符串转为二进制
client_socket.send(b'Welcome My ComputerC!')

# 接收信息，解码
data = client_socket.recv(1024).decode()
print(f'服务器端收到来自{address}的消息：{data}')

# 释放资源
client_socket.close()

# 关闭
# server.close() 服务器端一般不关闭
```

```python
import socket

# 1. 创建套接字：指定 UDP 协议 (SOCK_DGRAM)
server_socket = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)

# 2. 绑定地址和端口
server_address = ('127.0.0.1', 9999)
server_socket.bind(server_address)
print(f"UDP 服务器已启动，正在监听 {server_address}...")

try:
    while True:
        # 3. 接收数据
        # UDP 使用 recvfrom，因为它不知道是谁发来的，所以要同时获取数据和地址
        data, addr = server_socket.recvfrom(1024)
        print(f"收到来自 {addr} 的消息: {data.decode('utf-8')}")
        
        # 4. 发送响应
        # UDP 使用 sendto，必须指定发给谁 (addr)
        server_socket.sendto("收到UDP消息！".encode('utf-8'), addr)
except KeyboardInterrupt:
    print("\n服务器关闭。")
finally:
    server_socket.close()
```

```python
import socket

"""
客户端开发：
```

### 字符串转换

网络中的数据以二进制byte类型进行传递。

| 函数               | 函数说明                                                     |
| ------------------ | ------------------------------------------------------------ |
| `encode(encoding)` | 把字符串转化为二进制数据。`encoding`表示编码格式，默认为utf-8。 |
| `decode(encoding)` | 把二进制数据转化为字符串。`encoding`表示编码格式，默认为utf-8。 |

如果乱码，则编解码不同。

英文字母、数字、特殊符号在码表中占一个字节；中文在gbk中占两个字节，在utf-8中占三个字节。

> 二进制也可以使用`b''`，但是对中文无效。

```python
data = "我是天才"
print(data) # 我是天才

data_code = data.encode()
print(data_code) # b'\xe6\x88\x91\xe6\x98\xaf\xe5\xa4\xa9\xe6\x89\x8d'

data_code = data.encode('gbk')
print(data_code) # b'\xce\xd2\xca\xc7\xcc\xec\xb2\xc5'
```

一个`\`就代表一个字节。

### TCP网络程序的注意点

1. TCP服务端程序**必须绑定端口号**，否则客户端找不到这个TCP服务端程序，为了更稳定，建议把IP也绑定。
2. accept()前的套接字是被动套接字，只负责接收新的客户端的连接请求，不能收发消息。
3. 当TCP客户端程序和TCP服务端程序连接成功后，TCP服务器端程序会产生一个**新的套接字**，用于收发客户端消息。
4. 若关闭accept()返回的被动连接套接字，则表示和这个客户端已经通信完毕。
5. 对于服务器端socket，关闭时需谨慎。
6. 当客户端的套接字调用close后，服务器端的recv会解阻塞，返回的数据长度为0，**用于判断客户端是否已经下线**。

## 使用循环模拟多轮交互

```python
import socket

"""
服务器端开发：
    1. 创建服务器端的套接字对象
    2. 绑定IP与端口号
    3. 设置最大监听数
    4. 等待客户端相应
    5. 给客户端发送消息
    6. 接收客户端的信息并打印
    7. 释放资源
"""
# 创建服务器端的套接字对象（IPv4，TCP）
server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 绑定IP与端口号
server.bind(('192.168.0.160', 10086))

# 设置最大监听数
server.listen(5)

# 等待连接
while True:
    try:
        print('正在等待客户端建立连接...')
        client_socket, address = server.accept()
        print('客户端建立连接成功！')

        # 发送消息，需要把字符串转为二进制
        client_socket.send(b'Welcome My ComputerC!')

        # 接收信息，解码
        data = client_socket.recv(1024).decode()
        print(f'服务器端收到来自{address}的消息：{data}')

        # 释放资源
        client_socket.close()
    except:
        pass
"""
使用循环模拟，try保证客户端代码出错时不会中断程序的运行。
```
