# 概述

`threading` 是 Python 标准库中用于实现多线程并发编程的高级模块。使用时需导入该模块，通过实例化 `Thread` 类或继承该类来创建线程，并调用 `start()` 方法启动、`join()` 方法等待结束，当需要在 I/O 密集型任务（如网络请求、文件读写）中提升程序并发能力与响应速度时，就可以使用该模块。

## 核心作用

1. 并发执行任务

   允许在单个进程中同时运行多个线程，充分利用 I/O 等待期间的 CPU 空闲时间，显著提升 I/O 密集型任务的吞吐量。

2. 线程生命周期管理

   提供线程的创建、启动、暂停、等待及销毁等完整的生命周期控制接口。

3. 线程同步与通信

   提供锁、条件变量、事件、信号量等多种同步原语，解决多线程环境下的资源竞争与数据一致性问题。

4. 后台任务处理

   支持守护线程（Daemon Thread），使后台任务能随主线程退出而自动终止，避免程序阻塞。

## 核心类与工具

- `Thread`：线程类，用于创建和管理线程实例。
- `Lock`：互斥锁，确保同一时刻只有一个线程访问共享资源。
- `RLock`：可重入锁，允许同一线程多次获取同一把锁而不会死锁。
- `Condition`：条件变量，用于复杂的线程间通信与协调（如生产者-消费者模型）。
- `Event`：事件标志，用于线程间简单的状态通知（等待某个事件发生）。
- `Semaphore` / `BoundedSemaphore`：信号量，用于限制同时访问特定资源的线程数量。
- `Timer`：定时器线程，在指定延迟后执行某个函数。
- `Barrier`：线程屏障，要求指定数量的线程全部到达后才能继续执行。
- `local`：线程本地数据，为每个线程提供独立的数据存储空间。

## 常用模块级函数

| 函数名称             | 说明                               |
| -------------------- | ---------------------------------- |
| `current_thread()`   | 返回当前正在执行的线程对象         |
| `active_count()`     | 返回当前存活的线程数量             |
| `enumerate()`        | 返回当前所有存活线程对象的列表     |
| `main_thread()`      | 返回主线程对象                     |
| `settrace(func)`     | 为所有线程设置跟踪函数（用于调试） |
| `setprofile(func)`   | 为所有线程设置性能分析函数         |
| `stack_size([size])` | 获取或设置新建线程的栈大小         |

# `Thread`

`threading.Thread` 是 Python 标准库 `threading` 模块中用于创建和管理独立执行线程的核心类。使用时需通过实例化该类并传入目标函数，或继承该类并重写 `run()` 方法来定义线程逻辑，随后调用 `start()` 方法启动线程，当需要在 I/O 密集型任务中实现并发执行、提升程序响应速度或处理后台任务时，就可以使用该类。

## 创建对象时的格式

```python
threading.Thread(
    group=None,  # 保留参数，目前未实现，必须为 None
    target=None,  # 可选，线程启动时要调用的可调用对象（函数或方法）
    name=None,  # 可选，线程的名称，默认为 "Thread-N"
    args=(),  # 可选，传递给 target 的位置参数元组
    kwargs={},  # 可选，传递给 target 的关键字参数字典
    *,  # 强制后续参数必须使用关键字传参
    daemon=None  # 可选，是否为守护线程，默认为 None（继承创建者线程的属性）
)
```

## 参数详解

| 参数名称 | 作用说明                                     | 可选值或类型说明                                             |
| -------- | -------------------------------------------- | ------------------------------------------------------------ |
| `group`  | 线程组参数，目前未实现，保留供未来扩展使用。 | **必须为 `None`**                                            |
| `target` | 指定线程启动时自动调用的函数或可调用对象。   | **可调用对象**：<br />例如 `func`、`obj.method`，默认为 `None` |
| `name`   | 设置线程的名称，用于调试和日志识别。         | **字符串**：<br />例如 `"Worker-Thread"`，默认为 `"Thread-N"` |
| `args`   | 传递给 `target` 函数的位置参数。             | **元组**：<br />例如 `(arg1, arg2)`，默认为空元组 `()`       |
| `kwargs` | 传递给 `target` 函数的关键字参数。           | **字典**：<br />例如 `{"key": "value"}`，默认为空字典 `{}`   |
| `daemon` | 设置线程是否为守护线程。                     | **布尔值或 `None`**：<br />`True`（守护线程）、<br />`False`（非守护线程）、<br />`None`（继承创建者线程属性） |

## 常用属性

| 属性名称 | 说明                                                    |
| -------- | ------------------------------------------------------- |
| `name`   | 获取或设置线程的名称                                    |
| `ident`  | 获取线程的唯一标识符（整数），线程未启动时为 `None`     |
| `daemon` | 获取或设置线程是否为守护线程（必须在 `start()` 前设置） |

## 常用方法

| 方法名称             | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| `start()`            | 启动线程，安排 `run()` 方法在独立线程中执行（每个线程对象最多调用一次） |
| `run()`              | 线程的执行体，通常通过 `target` 参数指定，或在子类中重写     |
| `join(timeout=None)` | 阻塞当前线程，直到目标线程终止或超时（`timeout` 为秒数）     |
| `is_alive()`         | 返回线程是否仍处于运行状态（从 `start()` 到 `run()` 结束）   |

`threading.Thread` 对象主要有两种标准的使用方法：一种是直接实例化并传入目标函数，另一种是继承 `Thread` 类并重写 `run()` 方法。

## 代码示例

### 实例化

这种方式适用于简单的任务，无需定义新的类，直接通过 `target` 参数指定要执行的函数。

```python
import threading
import time

# 1. 定义一个普通的函数作为线程任务
def task(name, seconds):
    print(f"线程 {name} 开始执行...")
    time.sleep(seconds)  # 模拟耗时操作
    print(f"线程 {name} 执行完毕！")

# 2. 实例化 Thread 对象，传入 target 函数及其参数
thread1 = threading.Thread(target=task, args=("A", 2))
thread2 = threading.Thread(target=task, kwargs={"name": "B", "seconds": 1})

# 3. 启动线程
thread1.start()
thread2.start()

# 4. 等待线程执行完毕
thread1.join()
thread2.join()

print("所有线程执行结束，主线程继续。")
```

### 继承 Thread 类

这种方式适用于复杂的任务，可以将线程的逻辑、状态和数据封装在一个类中，代码结构更清晰，面向对象特性更强。

```python
import threading
import time

# 1. 继承 threading.Thread 类
class MyTaskThread(threading.Thread):
    # 2. 重写 __init__ 方法以接收自定义参数
    def __init__(self, name, seconds):
        super().__init__()  # 必须调用父类的初始化方法
        self.name = name
        self.seconds = seconds

    # 3. 重写 run() 方法，定义线程的具体执行逻辑
    def run(self):
        print(f"线程 {self.name} 开始执行...")
        time.sleep(self.seconds)  # 模拟耗时操作
        print(f"线程 {self.name} 执行完毕！")

# 4. 实例化自定义的线程类
thread1 = MyTaskThread("X", 2)
thread2 = MyTaskThread("Y", 1)

# 5. 启动线程（依然调用 start()，而不是直接调用 run()）
thread1.start()
thread2.start()

# 6. 等待线程执行完毕
thread1.join()
thread2.join()

print("所有线程执行结束，主线程继续。")
```

## `run()` 与 `start()`

在 `threading.Thread` 类中，`run()` 与 `start()` 是两个功能完全不同但紧密相关的方法。其核心区别在于**是否真正创建了新的线程**。

1. `start()` 方法

   用于**真正启动一个新线程**。调用此方法后，操作系统会分配一个新的线程，并在这个新线程中自动调用 `run()` 方法。这是实现多线程并发的唯一正确入口。

2. `run()` 方法

   仅仅是**线程的执行体**（即包含具体业务逻辑的普通方法）。如果直接调用 `run()` 方法，它只会在当前线程（通常是主线程）中作为一个普通函数顺序执行，**不会**创建任何新线程，也就无法实现并发。

> **简单理解**
>
> `run` 是执行线程中的函数，而 `start` 是创建线程并执行函数。

### 详细对比表格

| 对比维度           | `start()` 方法                                              | `run()` 方法                                            |
| ------------------ | ----------------------------------------------------------- | ------------------------------------------------------- |
| **核心作用**       | 启动新线程，并调度 `run()` 方法执行                         | 定义线程的具体执行逻辑（业务代码）                      |
| **是否创建新线程** | **是**，会触发操作系统创建新线程                            | **否**，仅在当前线程中顺序执行                          |
| **调用次数限制**   | 每个线程对象**只能调用一次**，重复调用会抛出 `RuntimeError` | 可以被多次调用，无次数限制                              |
| **执行方式**       | 异步执行，调用后立即返回，不阻塞当前线程                    | 同步执行，必须等待其执行完毕才能继续后续代码            |
| **使用场景**       | 作为启动线程的唯一标准入口                                  | 通常由 `start()` 内部自动调用，或在子类中重写以定义逻辑 |

### 代码示例对比

以下示例直观展示了两种调用方式在并发效果上的巨大差异：

```python
import threading
import time

def task(name):
    print(f"任务 {name} 开始")
    time.sleep(1)
    print(f"任务 {name} 结束")

# 1. 正确用法：使用 start() 启动线程
t1 = threading.Thread(target=task, args=("A",))
t2 = threading.Thread(target=task, args=("B",))

t1.start()  # 真正启动新线程，任务 A 在后台并发执行
t2.start()  # 真正启动新线程，任务 B 在后台并发执行

# 输出结果（并发）：
# 任务 A 开始
# 任务 B 开始
# 任务 A 结束
# 任务 B 结束
# （总耗时约 1 秒）

# --- 分割线 ---

# 2. 错误用法：直接调用 run() 方法
t3 = threading.Thread(target=task, args=("C",))
t4 = threading.Thread(target=task, args=("D",))

t3.run()  # 不会创建新线程，仅在主线程中顺序执行
t4.run()  # 不会创建新线程，仅在主线程中顺序执行

# 输出结果（串行）：
# 任务 C 开始
# 任务 C 结束
# 任务 D 开始
# 任务 D 结束
# （总耗时约 2 秒）
```

### 核心总结

**永远不要直接调用 `run()` 方法来启动线程**。`run()` 方法的设计初衷是供 `start()` 内部调用，或在继承 `Thread` 类时被重写以封装业务逻辑。启动线程的唯一正确方式始终是调用 `start()` 方法。

# 守护线程

## 定义与本质

守护线程（Daemon Thread）是一种在后台运行的特殊线程，其生命周期完全依赖于主程序（或非守护线程）。当程序中所有的非守护线程（用户线程）执行完毕并退出后，Python 解释器会强制终止所有仍在运行的守护线程，随后程序自动退出。守护线程不会阻止程序的退出。

> 也就是说，**进程**会等待所有非守护线程结束才退出。



## 核心作用

守护线程主要用于执行那些“可有可无”的后台辅助性任务，其核心作用体现在以下维度。

1. 后台服务支持

   为程序提供非关键的后台服务，如日志记录、监控采集、心跳检测等。

2. 自动清理资源

   随主程序的生命周期自动结束，避免程序退出时因后台线程未关闭而导致的进程挂起（僵尸进程）。

3. 简化生命周期管理

   无需手动编写复杂的线程停止逻辑，程序退出时守护线程会被自动强制销毁。

## 使用流程

在 Python 中，通过 `threading` 模块创建和管理守护线程。

### 创建与设置守护线程

必须在调用 `start()` 方法启动线程之前，将线程的 `daemon` 属性设置为 `True`。

```python
import threading
import time

def background_task():
    while True:
        print("守护线程正在运行...")
        time.sleep(1)

# 1. 创建线程对象
thread = threading.Thread(target=background_task)

# 2. 设置为守护线程（必须在 start() 之前设置）
thread.daemon = True 

# 3. 启动线程
thread.start()

# 主线程继续执行其他任务
print("主线程即将结束...")
time.sleep(3)
print("主线程结束，守护线程将随之终止")
```

### 继承父线程的守护状态

若创建线程时未显式指定 `daemon` 属性，新线程会默认继承创建它的父线程的守护状态。由于主线程默认是非守护线程，因此新创建的线程默认也是非守护线程。

## 注意事项

1. 资源清理不保证执行

   当主程序退出时，守护线程会被强制终止，这意味着线程中的 `finally` 代码块、上下文管理器（`with` 语句）的退出逻辑**不保证被执行**。因此，严禁在守护线程中执行关键的文件写入、数据库连接关闭等需要确保完成的操作。

2. 不适合 I/O 操作

   由于可能被随时中断，守护线程不适合处理需要保证数据完整性的 I/O 操作（如写文件、发送重要网络请求），否则可能导致数据损坏或文件写入不完整。

3. 子线程继承特性

   在守护线程中创建的子线程，默认也会继承守护状态，自动成为守护线程。

## 适用场景

| 场景类型       | 是否适用守护线程 | 典型示例                                                     |
| -------------- | ---------------- | ------------------------------------------------------------ |
| **适用场景**   | **是**           | 日志记录、系统监控、心跳检测、缓存定期刷新。                 |
| **不适用场景** | **否**           | 数据库事务操作、重要文件写入、核心业务逻辑处理、资源释放与清理。 |

# Lock

`threading.Lock` 是 Python 标准库 `threading` 模块中提供的一种最基础的同步原语，通常被称为互斥锁。使用时需通过实例化 `threading.Lock()` 创建锁对象，并在访问共享资源前调用 `acquire()` 方法获取锁（也可以理解为**申请**），操作完成后调用 `release()` 方法释放锁（推荐使用 `with` 语句进行上下文管理），当多个线程需要安全地修改同一个共享变量或资源，以防止数据竞争和竞态条件时，就可以使用该类。

> 线程之间同一把锁才有意义，因为锁的本质就是阻塞，可以理解为 `input` 函数，等待锁就是在等待输入，拿到了锁才会往下执行。

## 创建对象时的格式

```python
threading.Lock()  # 无需传入任何参数，直接实例化即可创建一个处于未锁定状态的互斥锁对象
```

## 参数详解

| 参数名称 | 作用说明                                    | 可选值或类型说明                         |
| -------- | ------------------------------------------- | ---------------------------------------- |
| 无       | `threading.Lock` 的构造函数不接受任何参数。 | **无**：直接调用 `threading.Lock()` 即可 |

## 常用属性与常用方法

| 属性/方法名称                        | 说明                                                         |
| ------------------------------------ | ------------------------------------------------------------ |
| `acquire(blocking=True, timeout=-1)` | 获取锁。<br />若 `blocking` 为 `True`（默认），则阻塞直到获取成功；<br />若为 `False`，则立即返回 `True`（成功）或 `False`（失败）。<br />`timeout` 可设置最长等待秒数。 |
| `release()`                          | 释放锁。必须在锁被获取后调用，否则会抛出 `RuntimeError` 异常。 |
| `locked()`                           | 返回锁当前的状态。若锁已被获取，返回 `True`；<br />若处于未锁定状态，返回 `False`。 |

# RLock

`threading.RLock` 是 Python 标准库 `threading` 模块中提供的一种可重入锁（Reentrant Lock）。使用时需通过实例化 `threading.RLock()` 创建锁对象，并在访问共享资源前调用 `acquire()` 方法获取锁（也可以理解为**申请**），操作完成后调用 `release()` 方法释放锁（推荐使用 `with` 语句进行上下文管理），当同一个线程需要在持有锁的情况下再次获取同一把锁（例如在递归函数或嵌套的同步方法中），以防止死锁发生时，就可以使用该类。

## 创建对象时的格式

```python
threading.RLock()  # 无需传入任何参数，直接实例化即可创建一个处于未锁定状态的可重入锁对象
```

## 参数详解

| 参数名称 | 作用说明                                     | 可选值或类型说明                          |
| -------- | -------------------------------------------- | ----------------------------------------- |
| 无       | `threading.RLock` 的构造函数不接受任何参数。 | **无**：直接调用 `threading.RLock()` 即可 |

## 常用属性与常用方法

| 属性/方法名称                        | 说明                                                         |
| ------------------------------------ | ------------------------------------------------------------ |
| `acquire(blocking=True, timeout=-1)` | 获取锁。<br />若 `blocking` 为 `True`（默认），则阻塞直到获取成功；<br />若为 `False`，则立即返回 `True`（成功）或 `False`（失败）。<br />`timeout` 可设置最长等待秒数。<br />与 `Lock` 不同，同一线程可多次调用此方法。 |
| `release()`                          | 释放锁。每次调用 `acquire()` 都必须有对应的 `release()`。<br />只有当所有获取次数都被释放后，锁才会真正变为未锁定状态。 |
| `locked()`                           | 返回锁当前的状态。若锁已被获取（无论被获取了多少次），返回 `True`；<br />若处于未锁定状态，返回 `False`。 |

## 与 `Lock` 的区别

| 对比维度     | `threading.Lock`                                             | `threading.RLock`                                            |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **重入性**   | 不可重入。<br />同一线程在持有锁时再次 `acquire()` 会立即死锁。 | 可重入。<br />同一线程可多次 `acquire()`，内部维护计数器。   |
| **释放要求** | 一次 `acquire()` 对应一次 `release()`。                      | `acquire()` 与 `release()` 必须成对出现，<br />次数必须完全匹配。 |
| **性能开销** | 较低，结构简单。                                             | 略高，需要额外维护持有线程的标识和重入计数器。               |
| **适用场景** | 简单的共享资源保护，无嵌套调用。                             | 递归算法、嵌套的同步方法、复杂的类内部调用。                 |

# 死锁

死锁（Deadlock）是指在多线程编程中，两个或多个线程因为争夺资源而陷入的一种**永久阻塞状态**。在这种状态下，每个线程都持有一部分资源，同时又在等待其他线程释放其所需的资源，导致所有线程都无法继续执行，程序彻底卡死。

针对提到的“同一线程在持有锁时再次 `acquire()` 会立即死锁”这一特定场景，这属于**单线程死锁**（或称为自死锁）。

## 单线程死锁的发生原理

当使用不可重入的普通锁（`threading.Lock`）时，如果同一个线程在已经获取了该锁的情况下，再次尝试获取同一把锁，就会发生死锁。具体过程如下：

1. 线程 A 成功获取了锁，开始执行业务逻辑。
2. 在业务逻辑的执行过程中（例如在嵌套函数或递归调用中），线程 A 再次尝试获取同一把锁。
3. 由于普通锁不可重入，且锁正被线程 A 自己持有，线程 A 会进入阻塞等待状态，等待锁被释放。
4. 然而，锁的释放代码在第一次获取之后，线程 A 因为阻塞在第二次获取上，永远无法执行到释放代码。
5. 最终，线程 A 陷入了“自己等待自己”的死循环，程序永久卡死。

## 代码示例

```python
import threading

lock = threading.Lock()

def nested_task():
    # 第一次获取锁（成功）
    lock.acquire()
    try:
        print("外层函数获取了锁")
        # 在持有锁的情况下，再次尝试获取同一把锁
        # 由于 Lock 不可重入，这里会永久阻塞，导致死锁
        lock.acquire() 
        try:
            print("内层函数获取了锁")
        finally:
            lock.release()
    finally:
        lock.release()

nested_task()
```

## 解决方案

为了避免这种单线程死锁，Python 提供了 `threading.RLock`（可重入锁）。`RLock` 内部维护了一个计数器和持有线程的标识：

- 当同一线程多次 `acquire()` 时，计数器会递增，而不会阻塞。
- 只有当 `release()` 的调用次数与 `acquire()` 的调用次数完全匹配时，锁才会被真正释放。

## 经典的多线程死锁

除了单线程死锁，更常见的是多线程死锁。例如：

1. 线程 A 持有锁 1，等待锁 2。
2. 线程 B 持有锁 2，等待锁 1。
3. 两者互相等待，形成死锁环路。

```py
import threading
import time

lock_1 = threading.Lock()
lock_2 = threading.Lock()

def task1():
    lock_1.acquire()
    time.sleep(1)
    lock_2.acquire()
    print(11)
    lock_2.release()
    print(111)
    lock_1.release()
    print(1111)

def task2():
    lock_2.acquire()
    time.sleep(1)
    lock_1.acquire()
    print(22)
    lock_1.release()
    print(222)
    lock_2.release()
    print(2222)

t1 = threading.Thread(target=task1)
t1.start()

t2 = threading.Thread(target=task2)
t2.start()
```

## 核心总结

1. 死锁的本质

   线程陷入了无法解开的等待循环。

2. 单线程死锁的触发条件

   使用普通 `Lock` 且在同一线程内嵌套获取同一把锁。

3. 预防手段

   在可能存在嵌套调用或递归的场景中，始终使用 `RLock` 代替 `Lock`。
